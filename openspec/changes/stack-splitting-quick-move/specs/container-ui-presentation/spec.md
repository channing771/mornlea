# Spec: container-ui-presentation

## MODIFIED Requirements

### Requirement: 容器换肤不改变统一栏位和权威交互

系统 SHALL 保留所有现有权威栏位编号与命令。前端只发送语义操作（槽位操作 MUST 携带按键类型与 Shift 修饰位），Go MUST 校验相位、当前视图身份与索引后调用对应的权威移动路径：左键两击调用既有整堆移动路径；右键两击调用部分数量移动路径（第二次点击带 Shift 为单件、否则为半组）；Shift+左键单击调用快捷搬运路径。两次点击类交互中第一次点击记录来源，第二次点击目标只发送一次请求并清除来源；确认前不改镜像。部分数量与快捷搬运的目标语义由权威侧定义（见 `stack-splitting` 规格），前端 MUST NOT 自行计算数量或落位。DOM 槽位是命中单源，装饰及 tooltip 不得扩大或遮挡点击；右键在面板上 MUST 只触发槽位语义操作，MUST NOT 弹出浏览器上下文菜单。

#### Scenario: 普通背包保持 36 格与十条配方命中
- **GIVEN** 已确认且符合本场景的容器状态
- **WHEN** 前端呈现并接收对应交互
- **THEN** 前端 MUST 呈现 36 玩家栏位与十条既有配方，DOM 点击与相应语义编号一一对应。

#### Scenario: 熔炉保持 39 格两次点击整堆移动
- **GIVEN** 已确认且符合本场景的容器状态
- **WHEN** 前端呈现并接收对应交互
- **THEN** 熔炉 MUST 保留 39 格统一语义；第二次有效点击后仅发送一次对应移动请求，确认前镜像逐格不变，输出格不得作为输入目标。

#### Scenario: 箱子保持 63 格两次点击整堆移动
- **GIVEN** 已确认且符合本场景的容器状态
- **WHEN** 前端呈现并接收对应交互
- **THEN** 箱子 MUST 保留 63 格统一语义；第二次有效点击后仅发送一次对应移动请求，确认前镜像逐格不变。

#### Scenario: 右键两击发起半组移动
- **GIVEN** 已确认的容器状态与一个非空来源格
- **WHEN** 玩家右键点击来源格后再右键点击目标格
- **THEN** 前端 MUST 只发送一次携带右键语义的部分移动请求（不带 Shift），数量由服务端推导，确认前镜像逐格不变

#### Scenario: Shift 右键两击发起单件移动
- **GIVEN** 已确认的容器状态与一个非空来源格
- **WHEN** 玩家右键点击来源格后再 Shift+右键点击目标格
- **THEN** 前端 MUST 只发送一次携带单件标志的部分移动请求，确认前镜像逐格不变

#### Scenario: Shift 左键单击发起快捷搬运
- **GIVEN** 已确认的容器状态与一个非空槽位
- **WHEN** 玩家 Shift+左键点击该槽位
- **THEN** 前端 MUST 发送一次快捷搬运请求且清除既有选中来源，确认前镜像逐格不变；浏览器上下文菜单 MUST NOT 出现
