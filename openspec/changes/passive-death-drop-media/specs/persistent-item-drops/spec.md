## MODIFIED Requirements

### Requirement: 图形客户端以固定资源呈现掉落物

图形客户端 SHALL 为权威镜像中的掉落物显示采样材质 atlas 的小方块，并只根据已确认的 server tick 和稳定掉落物 ID 计算浮动与旋转；CPU 与 GPU 容量 MUST 固定为 800 个实例，不得随运行时间、消息数量或帧数增长。层选择规则：可放置方块类物品走注册表既有材质（与世界同格同面采样一致）；食物类走牛肉/小麦层；全部可掉落物品 MUST 有层可采，未覆盖的缺口 MUST 在枚举末位追加原创程序化层（植物 31..54 不动）并溯源，MUST NOT 引入 Mojang/官方提取物。客户端动画 MUST NOT 反馈为服务端位置或存档状态。

#### Scenario: 权威更新在下一帧生效

- **GIVEN** 图形客户端已显示一个掉落物
- **WHEN** 客户端收到该 ID 的有效 upsert 或 remove
- **THEN** 下一帧使用新数量对应状态或不再显示该掉落物

#### Scenario: 动画不改变权威位置

- **GIVEN** 同一掉落物连续显示多个画面帧
- **WHEN** 客户端计算浮动和旋转
- **THEN** 掉落物镜像中的权威方块位置保持不变且不向服务端发送动画状态

#### Scenario: 掉落小方块采样材质而非纯色

- **GIVEN** 一个石头掉落与一个生牛肉掉落
- **WHEN** 客户端渲染掉落物
- **THEN** 石头小方块 MUST 采样与世界石头同源的材质层，生牛肉 MUST 采样牛肉层，两者 MUST 肉眼可辨且非同一纯色块

#### Scenario: 缺层追加保持植物区间冻结

- **GIVEN** 缺口清单中某可掉落物品无已有层可采
- **WHEN** 为其追加材质层
- **THEN** 新层 MUST 追加在枚举末位，植物 31..54 的层号 MUST 不变，且新层像素 MUST 为原创程序化并有溯源记录

#### Scenario: 自动验证不打开窗口

- **GIVEN** CI 或开发者运行掉落物协议、模拟、存档、客户端或渲染测试
- **WHEN** 自动验证执行
- **THEN** 测试 MUST 可在不启动或聚焦交互式游戏窗口的情况下完成
