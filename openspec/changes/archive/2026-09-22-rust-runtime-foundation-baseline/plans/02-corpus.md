# Corpus publication and loading execution plan

This packet implements repair areas 3 and 4 from `design.md`. The controller
uses Superpowers `subagent-driven-development`; each worker uses
`using-superpowers`, `test-driven-development`, `systematic-debugging` when a
failure is not understood, and `verification-before-completion`. Every node
receives an independent review under `requesting-code-review`; the controller
uses `receiving-code-review` before accepting or rejecting findings. Workers
must not edit `tasks.md`, `ledger.md`, `contracts.json`, or tracked case assets.

**Frozen export contract**

Move `RUNTIME_ORACLE_EXPORT_DIR` ownership to the runtime-oracle helper center.
Implement this error-returning test-only core there and a local equivalent in
companion:

```go
type generatedAsset struct {
    RelativePath string
    Data         []byte
}

func exportGeneratedAssets(
    repoRoot string,
    exportRoot string,
    producerID string,
    assets []generatedAsset,
) (string, error)

func exportGeneratedAssetsFromEnvironment(
    t *testing.T,
    repoRoot string,
    producerID string,
    assets []generatedAsset,
) string
```

The `testing.T` wrapper reads `RUNTIME_ORACLE_EXPORT_DIR`; an unset environment
variable returns `""` without writing, while a configured export calls the
fallible core and fails the test on error. Negative tests call the core
directly. `producerID` is a hard-coded slash-separated identifier chosen from:

- `runtime-oracle/protocol-frame`
- `runtime-oracle/domain-identity-values`
- `runtime-oracle/domain-values`
- `runtime-oracle/domain-command-control`
- `runtime-oracle/domain-command-inventory`
- `runtime-oracle/domain-event-player`
- `runtime-oracle/domain-event-world`
- `runtime-oracle/domain-event-inventory`
- `runtime-oracle/domain-event-people`
- `companion/agent-contract`

The helper resolves the export root through its nearest existing ancestor,
rejects repository containment and every symlink below that
ancestor, creates only the fixed producer child, and fails if that child
already exists. For each fixed relative asset it rejects absolute paths,
backslashes, `.`/`..`, symlink components and replacement, creates directories
with bounded permissions, and publishes with create-exclusive semantics.
No caller may supply the producer ID from corpus data.

**Red/green sequence**

1. Broaden `TestTestBinaryFlagsCannotRewriteTheFrozenCorpus` to reject every
   registered flag whose name contains `update` or whose usage mentions the
   tracked corpus. It must fail while the package-level flags remain.
2. Add helper tests for repository-contained roots, a symlinked ancestor, an
   escaping relative path, a preexisting producer child, and a successful
   multi-producer export. Every test uses `t.TempDir()` or a sibling temporary
   directory and records an unchanged tracked-tree digest.
3. Delete the eight runtime-oracle `-update-*` declarations and their tracked
   write branches. Each producer always compares generated bytes with frozen
   bytes; when the environment variable is set it additionally calls the
   shared exporter with its fixed producer ID.
4. Delete `-update-agent-contract-corpus` and its tracked write branch. Add the
   local companion exporter with the same validation order and its fixed
   producer ID; do not add a cross-module import.
5. Keep protocol frame export on the same helper, update both directory guides,
   and run `gofmt`. Scan the owned files for `flag.Bool`, `os.Rename`, or an
   `os.WriteFile` destination derived from `testdata/runtime-migration`.

**Expected results and validation**

```bash

go test ./packages/audit -count=1
git diff --exit-code -- testdata/runtime-migration
if rg -n 'flag\.Bool|update-.*corpus' \
  packages/tools/cmd/runtime-oracle/{domain_identity_values,domain_values,domain_command_control,domain_command_inventory,domain_event_player,domain_event_world,domain_event_inventory,domain_event_people}_test.go \
```

The final `rg` must return no producer rewrite flag; mentions in a negative
guard test are allowed only when they assert absence. A second export to the
same producer child must fail without changing the first export. The proposed
commit is `test(runtime-oracle): isolate corpus generation exports`.

**Exclusions and rollback**

Do not regenerate or stage corpus assets, add a production generator command,
weaken frozen comparisons, or share test code across Go modules. Reverting the
node restores only developer export behavior and leaves nodes 1.1–1.2 intact.

## Node 2.2: Make the Rust corpus loader fail closed

**Deliverable and prerequisites**

After node 1.1, turn `packages/engine/tests/runtime_corpus.rs` into a strict
root-parameterized independent consumer. Rust must reject every ambiguity the
Go inventory validator rejects before returning a case. Existing repository
callers retain small panic-on-error convenience wrappers; negative tests use a
fallible API and synthetic roots.

**Editable files**

- `packages/engine/tests/runtime_corpus.rs`
- `packages/engine/tests/AGENTS.md`
- `packages/engine/crates/mornlea_domain/Cargo.toml`
- `packages/engine/crates/mornlea_protocol/Cargo.toml`
- `packages/engine/Cargo.lock`
- new `packages/engine/crates/mornlea_domain/tests/corpus_loader.rs`

The protocol runtime contract, manifests and crate production sources are
read-only. Add `serde = "=1.0.229"` to both crates' `[dev-dependencies]`; this
is the version already present transitively in `Cargo.lock`, and is needed
because `serde_json` does not re-export the visitor traits. No production
dependency changes.

**Frozen interface**

Expose these test-support types and functions:

```rust
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum CorpusConsumer {
    Frame,
    Domain,
    ExternalAgentContract,
    ExternalRuntimeAuthority,
}

#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum InputFormat {
    Binary,
    Json,
}

#[derive(Debug)]
pub struct CorpusError {
    pub message: String,
}

pub fn try_load_cases_from_root(
    root: &Path,
    consumer: CorpusConsumer,
) -> Result<Vec<FrozenCase>, CorpusError>;

pub fn load_cases_for_consumer(consumer: CorpusConsumer) -> Vec<FrozenCase>;
pub fn load_case(id: &str) -> FrozenCase;
```

Extend `FrozenCase` with `version: String`, `consumer: CorpusConsumer`,
`input_format: InputFormat`, and `input_json: Option<serde_json::Value>`.
Binary cases store `None`; JSON cases are strictly decoded once and store
`Some`. `load_case` searches all four consumers and requires exactly one ID
match, preserving current protocol callers.

`try_load_cases_from_root` canonicalizes the supplied root once. Before loading
assets it validates schema version 2, the 8192-case maximum, unique family and
case IDs, case family membership, equality between each family's declared case
list and the actual cases, membership of each case version in
`supported_versions`, the `<family>/<version>/<label>` ID prefix, the closed
Go operation vocabulary, and nonempty decimal-u64 checkpoints. Then for every
manifest or asset relative path validates lexical form, walks each component
below the canonical root with `symlink_metadata`, rejects a symlink or
non-regular leaf, canonicalizes the leaf and rechecks containment. It applies
the 4 MiB manifest, 256 KiB JSON, 4 MiB binary and 8192-case budgets before
reads. A shared strict JSON decoder must use a custom serde visitor that rejects
duplicate object keys recursively; use it for the manifest, JSON inputs and
expected JSON. `input_format` accepts exactly `binary` or `json`, and
`rust_consumer` accepts exactly the four strings frozen in `design.md`. Every
input, expected and optional encoded asset digest is checked before its bytes
or parsed value enter `FrozenCase`. This is the shared manifest/case subset
named by the spec; live registry discovery, current identity comparison and
source-provenance reconciliation remain Go-only.

**Red/green sequence**

1. Create `corpus_loader.rs`, include the shared helper by path, and add
   synthetic-root tests named `rejects_duplicate_manifest_key`,
   `rejects_duplicate_input_key`, `rejects_duplicate_expected_key`,
   `rejects_unknown_input_format`, `rejects_unknown_consumer`,
   `rejects_trailing_json_input`, `rejects_symlinked_ancestor`, and
   `rejects_containment_escape`, plus table cases for unknown family,
   unsupported version, bad ID prefix, family case-list mismatch, invalid
   operation and empty/nondecimal checkpoints. Use a helper that writes a
   minimal valid schema 2 corpus under `tempfile`-free
   `std::env::temp_dir()` with a fixed `mornlea-corpus-loader-` prefix plus
   process ID and atomic counter. Its `Drop` guard canonicalizes the owned path,
   verifies the final file name still has that prefix and removes only that
   exact directory.
2. Record the red run: the manifest, correctly digested JSON-input, and
   correctly digested expected-value duplicate-key cases must each currently
   be accepted or misclassified; the unknown-format, unknown-consumer and
   trailing-input and ancestor-symlink cases must also fail for the intended
   reason. Every duplicate-key `Err` names its manifest, case ID or asset path so the three
   decoder call sites are independently proven.
3. Add `CorpusError`, the closed enums, strict JSON visitor, component walker,
   metadata checks, budgets and digest checks. Import visitor traits from the
   pinned direct `serde` dev dependency. Return errors containing the case ID
   or asset path; never catch an error and continue with another case.
4. Reimplement the convenience wrappers over the fallible loader and run the
   existing protocol frame corpus tests to prove compatibility.
5. Update the test-support guide and format with `cargo fmt`.

`test(engine): harden runtime corpus loading`.

**Exclusions and rollback**

Do not add a production crate dependency, change corpus schema 2, accept an
unknown future consumer, or interpret domain values in the loader. Reverting
this node restores the old test helper without changing Go evidence policy.
