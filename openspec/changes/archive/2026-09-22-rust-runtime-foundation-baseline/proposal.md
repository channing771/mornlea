## Why

The first implemented slice of `rust-runtime-foundation` established useful
offline evidence infrastructure and shared Rust domain values, but independent
closeout review found that several checked tasks do not yet prove executable
Go/Rust parity or bounded safe-Rust work. Extract and repair that slice before
the remaining protocol, storage and numerical migration proceeds, so later
changes depend on a reviewed canonical baseline rather than an oversized active
plan with overstated completion.

## What Changes

- Preserve the already implemented schema-2 corpus representation, isolated
  trace export, narrow audit boundary, framing seed case, service-free Agent
  contract evidence and shared Rust domain values through remote-player and
  companion publications.
- Separate in-progress inventory validation from complete acceptance, bind
  complete coverage to supported versions and callable consumers, and make
  trace comparison execute registered operations with fail-closed expected
  value loading.
- Remove tracked-corpus rewrite paths, align shared Rust corpus integrity checks
  with the Go validator, and execute every Rust-owned domain semantic case
  through Rust.
- Bound public domain text and semantic-batch validation before proportional
  work or fallible allocation.
- Publish only this narrow baseline as a canonical capability. Hostile/passive,
  projectile/drop and chat events, complete packet/save coverage, numerical
  APIs, pathfinding and final F1 acceptance remain separate successor changes.

## Capabilities

### New Capabilities

- `rust-runtime-foundation`: The reviewed executable-evidence substrate and
  bounded shared Rust domain contracts consumed by later runtime migration
  changes.

### Modified Capabilities

None.

## Impact

- Affected code: `packages/tools/cmd/runtime-oracle/`,
  `packages/shared/companion/` test producers, `packages/audit/` gates,
  `packages/engine/tests/runtime_corpus.rs`, and
  `packages/engine/crates/mornlea_domain/`.
- Protocol/save compatibility: protocol remains v45 and every save/ABI version
  remains unchanged. This change does not add or modify an online codec, save
  writer, runtime startup path or authority.
- Concurrency/performance: corpus generation remains offline and isolated.
  Domain public constructors reject more than 4096 semantic records before
  scanning, sorting or copying; packet-specific caps remain tighter.
- Dependencies: production dependency sets remain unchanged. Test-only corpus
  support continues to use the already approved locked dependencies.
- User-visible outcome: no gameplay or presentation change. Later Rust server
  and client work receives a reproducible, independently executed foundation.
- Non-goals: complete F1 acceptance, Godot work, a default-client switch,
  protocol/save version bumps, live-save access, a graphical window, or a
  second online authority.
- Rollback: revert the six repair areas independently while retaining the
  already committed baseline implementation and the current Go runtime.
