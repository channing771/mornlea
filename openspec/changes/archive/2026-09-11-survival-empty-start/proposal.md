# B-34 生存初始背包留空（proposal）

## 背景

发布列车（`docs/superpowers/plans/2026-08-26-basic-gameplay-backlog-replan.md` §近期产品目标）以「首夜生存 + 自给家园」为近期产品边界，第 10 行为 B-34：在关键资源已有自然取得路径后移除十四组整栈材料包，并锁定新世界可达性。前九行（A-01…A-05、B-04、B-02、B-33、B-27）均已交付：工作台与 3×3 合成、火把、三级剑、床、自然种子、可搬运水源、树苗与橡树再生、被动生物与熟肉。

当前服务端在 `LoadPlayer` 返回 `ErrPlayerNotFound` 时为新玩家构造一次性材料包：背包前 14 格各 `64` 个材料（圆石、平滑石、沙、砾石、橡木原木、橡木木板、树叶、玻璃、砖、白色羊毛、红色瓦块、黏土、雪块、苔藓圆石）。这既是「自给家园」的对立面（开局即拥有整栈建材），也是一个隐式依赖：材料包是**圆石在新世界里的唯一来源**，而 `RecipeFurnace` 与 `RecipeStoneSword` 都以圆石为原料。

侦察已按代码逐环核验了空背包起家链：徒手采掘橡木原木 `15` tick（`packages/server/sim/entity/mining.go:87-89`）→ 2×2 合成木板/工作台/木棍 → 放置工作台解锁 3×3（`packages/server/sim/entity/container.go:97-123`）→ 徒手采掘石头 `30` tick 可采收、掉落石料 → 石镐 → 采掘煤矿石 → 煤炭 + 木棍 = 火把；食物由自然短草种子→小麦→面包与被动生物生牛肉两条路径覆盖。四条关键能力均已可达。

但核验同时坐实一个回归：`CobblestoneID` 从不参与世界生成（材料表 `packages/shared/worldgen/generator.go:137-144` 无圆石、无岩浆、无结构生成），`ItemCobblestone` 的生产者只有 `BlockDrop(CobblestoneID)` 与材料包本身。若只清空材料包，熔炉、整套熔炼（铁锭/玻璃/砖块/熟牛肉）、铁制工具与**刚交付的空桶（B-02，需 3 铁锭）**会一并变为永久不可达，即本行会直接回退既有已交付内容。本 change 因此必须同时给出该缺口的裁决。

## 目标

- 缺失玩家的初始背包改为完全为空：不再有任何一次性发放，快捷栏与背包全部 36 格为空槽。
- 补齐被材料包掩盖的获取缺口，使「首夜生存 + 自给家园」的进程内容在空背包下仍然完整：熔炉与其后的熔炼链（铁锭、玻璃、砖块、熟牛肉）以及石剑等级必须重新可达。
- 用**价值闭包守卫**把「关键能力可达」变成可判定的回归门禁：以自然获取集合为起点按既有规则求不动点，四条关键能力与熔炼链所需物品必须落在闭包内，且闭包外的物品集合必须恰为已接受的装饰材料。
- 更新所有依赖材料包的测试夹具、跨模块源码守卫、文档与规格，使「开局空背包」成为唯一契约。

## 非目标

- 不新增方块、物品、配方编号或工具类型；不改变世界生成、engine ABI、client ABI、协议与任何存档 schema。
- 不为不自然生成的装饰材料（圆石、平滑石、苔藓圆石、白色羊毛、红色瓦块）补自然获取路径：它们被本行接受为「已不可得」，其自然化另立后续行（见 design.md D3）。
- 不做新手引导、教程提示、初始坐标保护或出生点友好化。
- 不改动已有玩家存档的任何一个栏位，不做任何形式的库存迁移、清理或回补。
- 不引入「首次进入世界时发放」等换皮发放机制。

## 用户可观察结果

- 新世界首次登录后背包与快捷栏完全为空，没有任何材料、种子或工具。
- 玩家徒手打树得到原木，合成木板、木棍与工作台；放下工作台后合成网格变为 3×3。
- 徒手挖石头得到石料，配木棍合成石镐；用石镐挖煤矿得到煤炭，与木棍合成火把——照明不再需要开局材料。
- 采除短草得到种子的概率性掉落不变，锄头翻地、种植、收获面包的农业闭环不变；生牛肉来自被动生物。
- 熔炉仍可由 3×3 石料圆环合成并发光；沙→玻璃、黏土→砖块、生牛肉→熟牛肉、铁矿→铁锭照常熔炼；用三块铁锭合成的空桶仍可舀水（B-02 内容不被回退）。
- 已有玩家的背包逐槽保持不变，历史材料包内容不会被清空或补发。

## 受影响的包或文档

- `packages/server/server/persistence`：缺失玩家的快照不再装载材料包；`players_snapshot.go` 的清单与构造函数移除。
- `packages/server/server`：`farming_loop_e2e_test.go`、`hunger_loop_e2e_test.go`（含 TCP parity 共用 runner）的登录就绪判定不再以「背包非空」为信号；新增空背包起家端到端脚本。
- `packages/shared/core`：`recipe.go` 的熔炉与石剑配方改用可徒手取得的石料；`sapling_acquisition_test.go` 的第三条守卫改指新初始背包契约；新增价值闭包守卫测试。
- 主规格同步：MODIFIED `common-block-materials`（缺失玩家空背包 + 新增价值闭包需求）、MODIFIED `authoritative-crafting`（熔炉与石剑配方原料）、MODIFIED `oak-sapling-regrowth`（「初始材料包」措辞改为「新玩家初始背包」）。
- 文档：`docs/notes/gameplay.md`、`docs/notes/limitations.md`、`README.md`、`docs/feature-backlog.md`、`docs/notes/progress.md`。

## 兼容性

- 无协议、存档 schema、engine ABI、client ABI 与 benchmark scenario 变更；版本矩阵全部保持（协议 v40、玩家 schema v8、区块 schema v9、metadata v5、`companions.ai` v5、`hostile_mobs` v1、`passive_mobs` v1、engine ABI v11、client ABI v18、scenario v23）。
- 玩家存档格式不变：空背包只是缺失玩家快照的取值变化，不涉及字段增删或迁移链。
- 既有玩家存档逐槽保留，历史材料包内容继续存在且可用，服务端不会回收。
- 熔炉与石剑配方的原料由圆石改为石头属于**固定配方语义变更**：老存档中已合成的熔炉/石剑照常存在与使用，只在新的合成行为上生效；该变更由 `authoritative-crafting` 主规格的 MODIFIED 需求承载。
- 回退即 revert 本分支：无数据迁移、无版本号需回滚，唯一的存档影响是「新玩家不再获得材料包」，回退后自动恢复。
