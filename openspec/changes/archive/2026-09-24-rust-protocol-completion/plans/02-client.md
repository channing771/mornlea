# Client packet worker packets

Each node consumes [the boundary/evidence contract](01-boundaries.md#shared-packet-case-contract), [design.md](../design.md) §§1–4 and the exact client rows in [wire-matrix.md](../wire-matrix.md). All Go production code is read-only. A group owns the named Rust packet modules, one Rust integration test, one test-only Go producer and the exact family assets; the controller serializes `lib.rs`, `ORACLE/inventory.go` and manifest merges. For every listed family, record `protocol.client.<Name>/45/valid-decode`, `/valid-encode` and the named negative case below, with one checkpoint `0` and the exact C/state/ID key. The Rust consumer runs both operations, compares all fields and output bytes, tests every proper prefix truncation for fixed payloads <=256 bytes, and tests a trailing byte. The Go producer invokes `codec.Codec` with the actual `protocol` DTO and validates both paths. Every group tests a mutated public Rust struct against a short `0xa5` output buffer: semantic error must win and the buffer must remain unchanged. No packet produces authoritative world effects in F1.

## 2.1 — Movement, placement, resync and selection

**Predecessors:** 1.1–1.3. **Deliverable:** four Play C→S payloads with lossless fields and the correct protocol/authority split. **Editable:** `PROTOCOL/src/{player_input,place_block,request_chunk_resync,select_hotbar}.rs`, new `PROTOCOL/tests/protocol_client_control.rs`, new `ORACLE/protocol_client_control_test.go`, `CORPUS/cases/protocol/{PlayerInput,PlaceBlock,RequestChunkResync,SelectHotbar}/`, their routes in `ORACLE/inventory.go`, `PROTOCOL/AGENTS.md`. **Read-only:** Go `protocol/message.go`, `codec/codec_client.go`, `DOMAIN/src/input/control.rs`. **Interfaces:** the common fallible packet methods; `TryFrom<ClientPacket> for PlayIntent` later consumes raw `sequence` plus these checked payloads, never session/tick metadata.

| Family/key | Valid concrete value | Named negative and expected category |
|---|---|---|
| PlayerInput C/Play/0 | seq=0, axes −128/127, jump=true, yaw=−0.0, pitch=2.0, mining/eating/sprinting/sneaking=(1,0,1,0) | `nan-yaw` → invalid-value; `bool-two` → invalid-enum; finite pitch 2.0 and full i8 axes remain wire-valid |
| PlaceBlock C/Play/2 | seq=0, yaw=1.25, pitch=−0.0, slot=8 | `slot-nine` → invalid-value; `infinite-pitch` → invalid-value |
| RequestChunkResync C/Play/3 | seq=0, dimension=1, chunk=(−1,0), have_revision=0 | `dimension-two` → invalid-enum; negative chunk coordinates stay valid |
| SelectHotbar C/Play/5 | seq=0, slot=8 | `slot-nine` → invalid-value |

**Red:** the baseline packet encoders have no caller-buffer API; a mutated slot or nonfinite float after construction can bypass earlier checks. **Implementation:** convert fields in wire order with LE integers and f32 bit preservation; do not clamp pitch, axes, yaw or revision at the protocol boundary. Validate complete mutable record before checked size/capacity. For each case, compare the Go-produced payload with Rust bytes and normalized fields; preserve `-0.0` bit pattern, not just numeric equality. **Validation:** the two `tasks.md` commands plus `cargo test -p mornlea_protocol --test runtime_contract --locked` from `packages/engine`. **Exclusions:** movement-axis [-1,1], target raycast, resync policy and slot contents remain authority-owned. **Rollback:** revert four modules plus group cases. **Commit:** `feat(protocol): qualify client control packets`.

## 2.2 — Ray action family

**Predecessors:** 1.1–1.3. **Deliverable:** five bounded ray-intent payloads, with no client-supplied target block or item. **Editable:** `PROTOCOL/src/{open_container,till_soil,bone_meal,collect_water,place_water}.rs`, new `PROTOCOL/tests/protocol_client_rays.rs`, new `ORACLE/protocol_client_rays_test.go`, `CORPUS/cases/protocol/{OpenContainer,TillSoil,BoneMeal,CollectWater,PlaceWater}/`, their routes in `ORACLE/inventory.go`, `PROTOCOL/AGENTS.md`. **Read-only:** Go `protocol/message*.go`, `codec/codec_client.go`, server ray/interaction tests. **Interfaces:** all five are `sequence:u64,yaw:f32,pitch:f32`; each uses the common fallible packet methods.

**Case table:** for each of the five keys (IDs 8,13,14,16,17 respectively), `valid-decode` and `valid-encode` use `sequence=0`, `yaw=-0.0`, `pitch=1.5`; `nan-yaw` changes the f32 bits to a quiet NaN and must reject before publication; `infinite-pitch` rejects; every proper truncation and a trailing byte reject. The valid value has no target position, held item, container kind or result in the wire payload. Baseline `encode()` returns `Vec` and may accept a mutated public nonfinite value through fail-first `expect`, which is the intended red.

**Implementation:** use one private field-writing pattern, not a second exported ray payload type that would erase packet keys; call `validate()` before `encoded_len()`/capacity, then write exactly 16 bytes in order. Go producer uses each actual type and key. **Validation:** commands in `tasks.md` plus Go `TestPrimitiveFloatRejectsNonFiniteValues`. **Exclusions:** ray geometry, held-item checks and mutation are F2 server rules. **Rollback:** revert five modules plus cases. **Commit:** `feat(protocol): qualify client ray actions`.

## 2.3 — Simple inventory and crafting commands

**Predecessors:** 1.1–1.3. **Deliverable:** six small commands with distinct slot/sequence rules. **Editable:** `PROTOCOL/src/{move_inventory_stack,move_crafting_stack,close_container,drop_selected_item,equip_armor,take_crafting_output}.rs`, new `PROTOCOL/tests/protocol_client_inventory.rs`, new `ORACLE/protocol_client_inventory_test.go`, `CORPUS/cases/protocol/{MoveInventoryStack,MoveCraftingStack,CloseContainer,DropSelectedItem,EquipArmor,TakeCraftingOutput}/`, their routes in `ORACLE/inventory.go`, `PROTOCOL/AGENTS.md`. **Read-only:** Go `protocol/message*.go`, `codec/codec_client.go`, Go stack/crafting tests. **Interfaces:** common fallible packet methods; semantic adapter preserves `sequence` separately and maps each payload to its existing `DOMAIN::Command` variant.

| Key | Valid concrete payload | Negative input and expected result |
|---|---|---|
| C/Play/6 MoveInventoryStack | seq=0, from=0, to=35 | from=36, to=36, or from=to → invalid-value |
| C/Play/7 MoveCraftingStack | seq=0, from=8, to=44 | from=9,to=44 (both inventory region), same slot or 45 → invalid-value |
| C/Play/10 CloseContainer | seq=0 | 7-byte truncation and one trailing byte → truncated/trailing |
| C/Play/11 DropSelectedItem | seq=0 | 7-byte truncation/trailing; no item count or location field may appear |
| C/Play/18 EquipArmor | seq=0 | 7-byte truncation/trailing; no target armor slot may appear |
| C/Play/15 TakeCraftingOutput | seq=1 | seq=0 → invalid-value, even though other command sequences accept 0 |

**Red:** mutated public slots and zero TakeCraftingOutput after construction are not guaranteed to be checked by the current infallible encoders. **Implementation:** fixed LE u64 sequence first; slot bytes only for the two move packets. Check `from != to`, exact view bounds and the crafting two-inventory exclusion before capacity. Do not impose the personal-grid 4..8 authority rule in the protocol. **Validation:** commands in `tasks.md` and `go test ./packages/shared/network/codec -run 'TestSmallPacket' -count=1`. **Exclusions:** inventory contents, count, output recipe and equipped slot are server-owned. **Rollback:** revert six modules plus cases. **Commit:** `feat(protocol): qualify inventory command bytes`.

## 2.4 — Container and view-addressed stack commands

**Predecessors:** 1.3 and 2.3. **Deliverable:** four commands refuse a malformed real container and preserve the exact absent sentinel, including the current constructor/decode asymmetry. **Editable:** `PROTOCOL/src/{move_container_stack,move_stack_partial,container_ref}.rs`, new `PROTOCOL/tests/protocol_client_stack_views.rs`, new `ORACLE/protocol_client_stack_views_test.go`, `CORPUS/cases/protocol/{MoveContainerStack,MoveStackPartial,QuickMoveStack,DropStack}/`, their routes in `ORACLE/inventory.go`, `PROTOCOL/AGENTS.md`. **Read-only:** Go `protocol/message_stack_splitting.go`, `message_drop_stack.go`, `codec/stack_splitting_test.go`, `codec/drop_stack_test.go`. **Interfaces:** `ContainerRef::to_domain_present/optional` from 1.3; `validate_stack_view(view:u8, raw:&ContainerRef, indices:&[u8]) -> Result<Option<DOMAIN::ContainerRef>,ProtocolError>` is private and used by all three view-addressed commands. `MoveContainerStack` uses present conversion directly.

**Concrete table:** `MoveContainerStack` C/Play/9 uses a furnace ref `(dimension0,chunk−1/2,kind0,slot31,generation1)`, from0,to37; to38 rejects because it is the furnace output, and from=to rejects. Chest kind1 slot15 uses view index62 valid, 63 invalid. `MoveStackPartial` C/Play/19 uses view2 with the same chest ref, from36,to62,single=true; from=to rejects but two crafting inventory-region indices are wire-valid. `QuickMoveStack` C/Play/20 uses view1, exact NONE, from44; `DropStack` C/Play/21 uses view0, exact NONE, slot35. For all three, view3, nonzero ref in view0/1, generation0 in view2, dimension256/−1, kind2, physical slot out of kind range, and index above 35/44/38/62 reject. `single` byte2 rejects. Each family gets valid decode/encode and its first listed negative plus the shared malformed-ref matrix.

**Red:** current `ContainerRef::read` narrows i32, current `validate_stack_split` does not validate a real ref, and `MoveContainerStack::new` skips real-reference validation. **Implementation:** read all 18 raw ref bytes with i32 dimension, never cast before checking. Validate view first, exact NONE for views0/1, real-ref conversion for view2, then view-specific index bounds and command-specific same-slot/output rules. For `MoveStackPartial`, do not add the stricter crafting or furnace-output policy that Go leaves to authority. Run validation again before writing a mutable DTO. **Validation:** tasks commands plus `go test ./packages/shared/network/codec -run 'TestStackSplit|TestDropStack' -count=1`. **Exclusions:** source stack count, transfer destination and world drop position are F2 rules. **Rollback:** revert four packet paths and cases, preserving 1.3's raw ref API. **Commit:** `fix(protocol): validate all stack-view references`.

## 2.5 — Chat command

**Predecessors:** 1.1–1.3. **Deliverable:** the unsequenced C/Play/12 text payload remains distinct from the 19 sequenced commands. **Editable:** `PROTOCOL/src/chat_command.rs`, new `PROTOCOL/tests/protocol_client_chat.rs`, new `ORACLE/protocol_client_chat_test.go`, `CORPUS/cases/protocol/ChatCommand/`, its routes in `ORACLE/inventory.go`, `PROTOCOL/AGENTS.md`. **Read-only:** Go `protocol/message_companion.go`, `codec/companion_wire.go`, `DOMAIN/src/input/chat.rs`, `DOMAIN/src/text.rs`. **Interfaces:** `ChatCommand {text}` validates against domain `CommandText`; later `TryFrom<ClientPacket> for PlayIntent` emits `Chat(ChatIntent)`, not a sequenced command.

**Cases:** `valid-decode`/`valid-encode` use `"@mira follow"`; exactly 1024 UTF-8 bytes admits, 1025 rejects before output, empty rejects, leading U+00A0/trailing space rejects, NUL/control rejects, invalid UTF-8 input and noncanonical string length reject; a valid text with a leading `@` is not interpreted/addressed by protocol, and a valid text without `@` remains wire-valid. Current allocating encoder has no caller-buffer API; mutated text must fail before capacity with no output changes. **Implementation:** use the canonical u32 length-prefixed UTF-8 wire format, domain lexical rule and exact byte count; no chat addressing, `/warp` handling, FIFO, session or sequence field. **Validation:** tasks commands plus `go test ./packages/shared/network/codec -run 'TestCompanionMessage' -count=1`. **Rollback:** revert module and case family. **Commit:** `feat(protocol): qualify chat command wire`.
