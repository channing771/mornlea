## MODIFIED Requirements

### Requirement: 图形客户端以固定资源呈现掉落物
图形客户端 SHALL 为权威镜像中的掉落物显示简化物品色块，并只根据已确认的 server tick、稳定掉落物 ID 与已确认镜像方块计算浮动、旋转与下落；CPU 与 GPU 容量 MUST 固定为 800 个实例，不得随运行时间、消息数量或帧数增长。呈现下落 SHALL 与角色共用重力积分形状：每权威 tick（50ms）`v += g·dt`、终端速度钳制、着陆停留，`g` 与终端速度取客户端生效 tunables；支撑高度为掉落方块位置下方首个不透明方块顶面（向下扫描定界 16 格；无数据或超深时按生成高度保持）；着陆后保留浮动与旋转。客户端动画与下落 MUST NOT 反馈为服务端位置或存档状态。

#### Scenario: 权威更新在下一帧生效
- **GIVEN** 图形客户端已显示一个掉落物
- **WHEN** 客户端收到该 ID 的有效 upsert 或 remove
- **THEN** 下一帧使用新数量对应状态或不再显示该掉落物

#### Scenario: 动画不改变权威位置
- **GIVEN** 同一掉落物连续显示多个画面帧
- **WHEN** 客户端计算浮动和旋转
- **THEN** 掉落物镜像中的权威方块位置保持不变且不向服务端发送动画状态

#### Scenario: 无支撑掉落物加速下落至支撑面
- **GIVEN** 掉落物生成高度下方 3 格处有不透明方块顶面
- **WHEN** 客户端连续编码后续 tick 帧
- **THEN** 呈现高度 MUST 逐 tick 加速下降（增量递增）且 MUST NOT 低于支撑高度
- **AND** 着陆后浮动与旋转 MUST 继续

#### Scenario: 自动验证不打开窗口
- **GIVEN** CI 或开发者运行掉落物协议、模拟、存档、客户端或渲染测试
- **WHEN** 自动验证执行
- **THEN** 测试 MUST 可在不启动或聚焦交互式游戏窗口的情况下完成
