# flood-destroys-crops 设计

## Context

`internal/fluid` 的 `Replaceable(target, newLevel)` 是可替换判定的唯一谓词：空气恒真、源与更强流动水恒假、其余非流体一律不可替换。作物（`core.IsCrop`，`WheatStage0..7ID`）当前落入「实心方块」分支，因此挡水。流体写入的唯一汇聚点是 `sim.fluidWorld.SetBlock`——`internal/fluid` 自身不写世界、不懂物品，全部写入经它落区块并汇入 `recordChange`。掉落物的既有先例：玩家采掘成熟小麦的多产物结算在权威路径组批（`PrepareDropBatch` 预演 → 破坏 → 提交），预演失败整体不破坏；伙伴采掘在背包无空位时同样拒绝破坏。重扫不动点捷径（`fluidSourceIsFixedPoint` 与区段级快路径）复用同一个 `Replaceable` 谓词做保守判定。

## Goals / Non-Goals

**Goals**

- 作物格对流动水可替换，冲毁按采掘同表掉落，单 tick 内原子成立。
- 掉落槽满时零数据丢失：拒绝破坏 + 重试直至完成。
- 「平衡态是重扫的不动点」论证在新规则集下保持成立并更新文本。

**Non-Goals**

- 不改岩浆/推力（B-28/B-29）、不破坏耕地、不给伙伴开农业口子。
- 不引入任何 wire/schema/ABI/scenario 变化。

## Decisions

### D1 可替换判定的挂点：只改 `Replaceable` 一个谓词

作物可替换是流动规则的语义变更，唯一正确的位置是 `Replaceable` 本身：垂直优先与水平递减这两处写入判定、水源不动点捷径、区段级快路径全部经由这一个函数读世界，改一处即全链一致。
**被否决的替代方案**：在 `evalCell` 里为作物加特判传播分支——会让同一语义散落在两处，且不动点捷径（它独立调用 `Replaceable`）会与规则脱节，把「邻作物的源」误判成不动点跳过入队，水面在农田边永久卡死。

### D2 冲毁结算挂在 `fluidWorld.SetBlock`，`internal/fluid` 保持不懂物品

`SetBlock` 是全部流体写入的唯一汇聚点（含未来新写者），在这里检测「旧值 ∈ 作物 && 新值 ∈ 流体」即可保证冲毁恰好结算一次（Advance 对每个目标格每 tick 只提交一次合并后的写入）。掉落的物品知识留在 sim 侧，fluid 包继续只认方块编号。
**被否决的替代方案**：(a) 让 fluid 包回调 sim 结算——包依赖倒置，fluid 必须定义回调接口并处理回调失败语义，复杂度无收益；(b) 在 evalCell 返回值里携带「破坏事件」——改变 fluid 包内部数据流，波及全部 property 测试，且仍需 sim 侧落地，两层都变。

### D3 掉落槽满：拒绝写入 + 目标格重新入队

预演（`PrepareDropBatch`）失败时本 tick 不写任何东西（方块不变、槽位不变），并把目标格按正常延迟重新入队。拾取释放槽位后重试自然完成。这与伙伴采掘「背包无空位不破坏」同一纪律，杜绝半掉落与静默丢失。
**被否决的替代方案**：(a) 照常破坏、丢弃产物——踩「真实 overflow / 数据丢失」门禁红线；(b) 拒绝后不重试、等外部事件唤醒——拾取释放槽位不触发 `enqueueFluidUpdate`，农田会被永久卡死在「该淹不淹」状态；(c) 把重试做成有界次数——上限取值无依据，无限重试的单格成本是一次入队 + 一次空求值，有界且无害。

### D4 掉落表与原子序：完全镜像采掘路径

成熟 = 1–3 小麦 + 1–3 种子，两类数量由 `cropYieldRolls`(worldSeed, 权威 tick, 维度, 方块坐标) 的纯整数哈希给出——与采掘、踩踏共用同一条产量哈希流，同一株作物在同一权威 tick 上被冲毁、被踩掉或被挖掉的产出逐件相同；未成熟 = 1 种子（`core.BlockDrop` 单产物）。执行顺序照抄多产物先例：`PrepareDropBatch` 预演 → 写流体 + `recordChange` → `CommitDropBatch`。多产物的知识继续只存在于权威结算路径，`core.BlockDrop` 的单一产物返回形状不动（其消费者面太大，Ruling 5 先例仍然成立）。

### D5 收敛性：作物→水单调，良基性不受影响

冲毁把作物格变成普通流体格，此后它只服从既有流动规则；被淹没的格子非空气，`advanceCrops` 的露天判据使其不可能再生作物，故不存在「水↔作物」振荡环，支撑关系良基结论原样保留。水源不动点捷径自动一致：邻格含作物的源不再满足「五邻均不可替换」，被正确排除出跳过集并入队——这是捷径语义的正确收紧而非放宽，增量正比于农田临水面。需要更新的只有论证文本（`Replaceable` 判定表注释、rescan 注释中对「任意其他非空气方块（实心）」的表述）与 spec 场景，无需改任何 rescan 代码。

## Risks / Trade-offs

- [重试项常驻队列占用预算] → 单格成本为一次入队 + 一次 `evalCell` 空转（目标仍是作物时求值产出写入、提交被拒），受 `FluidUpdatesPerTick` 硬约束顺延，最坏挤占同 tick 其他流体更新一个名额；农田规模下可忽略。测试钉住「拒绝期间每 tick 至多重试一次、不重复结算」。
- [既有 capture golden 漂移] → 18 个场景无农田临水构图；实施时跑 `make visual` 相关核查确认逐字节不变，若意外漂移先查根因不得重录。
- [性能数值漂移] → benchmark 钉死不注水更不受影响；如 perfcheck 数值变化仅记录不调阈值。

## Migration Plan

纯行为增强，无存档/协议迁移。回退 = revert 本 change 的实现提交；已冲毁的世界不会因回退恢复作物（接受，单向自然现象）。
