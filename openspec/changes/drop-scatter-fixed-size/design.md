## Context

当前 `dropScatterPlacementFor` 按 `m=ceil(sqrt(n))` 划分 cell 并以 `scale=min(1,0.84*cell/(2*0.251))` 缩小，测试把 1/0.75/0.38/0.25 四档钉死。实测全尺寸薄片 0.5 格宽（`dropFlakeSize`）、方块 0.25 格（`dropCubeSize`）：2×2 档全尺寸相邻交叠仅约 0.05 格（“小小重叠”），4 堆及以下可完全不出格；32 档 6×6 边角 cell 中心 0.875 加半宽 0.25 加最大抖动 0.006，探出上界 0.131（16 档实测约 0.095）。用户已接受该代价，规格取 0.14 裕量上界。

## Goals / Non-Goals

目标是全密度全尺寸、可辨认；保留分组、排序、唯一 cell、抖动、分层、800 容量、支撑与生命周期语义。非目标见 proposal.md。

## Decisions

1. `dropScatterPlacementFor` 删除密度缩放，scale 恒为 1；`bob` 取全幅 `dropFloatHeight`，`layerStep` 按全尺寸公式自然变大（17 堆起第二层约 0.68 格，接受为全尺寸的代价，不另设紧凑堆叠，避免层间穿插）。
2. XZ 不做钳制：钳制会把 6×6 边角两列压到同一坐标（仅剩抖动区分），反而损害可辨认；改为测试与规格允许 16/32 档最大 0.14 格探出（推导上界 0.131 加裕量），1/4 档仍不断言之外的零探出。
3. 否决“网格封顶 3×3 + 按 9 分层”：改动大且层数翻倍同样改变剪影；用户要的是最小改动下的全尺寸，按字面 scale 恒 1 落地。
4. 失败测试先行：改四档期望为 1 并改名去“缩放”语义；越界拆分为稀疏零探出 + 密集 0.14 探出上界 + 相邻中心最小距离（可辨下界）；层间净空与确定性测试保留并按全尺寸更新期望。

## Risks / Trade-offs

- 32 堆为全尺寸 pile，美观不如缩小版，但可辨认（用户已接受）。
- `drop-scatter.gif`、`drop-density.gif` 基线必须重出并目检；`avatar-walk.gif`、`break-burst.gif`、`avatar-detail.png` 不受影响不得重拍。
- 拾取仍按原方块中心，视觉探出不改变玩法（沿用既有“散落是纯呈现偏移”结论）。
