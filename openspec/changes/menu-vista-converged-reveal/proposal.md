# 主菜单全景收敛后揭示

## 背景

主菜单背景是固定种子的纯渲染层全景管线（menu-vista）：每帧只生成 4 个区块（`menuVistaChunksPerFrame = 4`），625 个区块约需 157 帧才生成完毕，烘焙与上传同样渐进推进。用户在菜单背后能直接看到地图一块一块浮现，观感等同「实时生成的加载过程」，不符合标题画面预期。

## 目标

- 全景装配收敛（待生成区块、待烘焙段、待上传与远环队列全部清空）之前，不向用户揭示部分装配的几何：等待期只渲染天空清屏底色，WebView 菜单 chrome 照常交互。
- 收敛后从相机脚本 tick 0 开始揭示全景，收敛后的帧内容与相机轨迹与现状逐帧一致（确定性不回退）。
- 提高装配泵速（每帧区块数 4 → 12）缩短等待窗口。

## 非目标

- 不改为预渲染视频/图片序列播放（渲染客户端无纹理/视频播放能力，且会丢失「与游戏同一渲染路径」的保真与既有 golden 口径）。
- 不改变全景的固定种子、相机脚本、LOD 远环与「不装配世界」红线。
- 不调整游戏内加载屏（world-loading-screen）与游戏相位流式行为。

## 用户可观察结果

- 进入主菜单：短暂的天空底色 + 可交互菜单，随后一次性呈现完整全景；不再出现区块逐块浮现。
- 全景照旧绕轴循环播放，同一收敛状态的帧与现状逐位一致。

## 受影响包

- `packages/client/cmd/mornlea/app`（`app_menu_vista.go`、`app_frame.go` 与测试）

## 兼容性影响

无协议、存档或 ABI 变更。收敛像素与现状一致，`main-menu`/`settings-menu` golden 无需重生成（capture 本就在收敛后钉帧）。
