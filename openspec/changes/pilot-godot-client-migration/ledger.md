## Rulings

- Ruling: begin with P0 and follow the approved P0–P7 dependency order — the revised pilot has 89 tasks and hard No-Go points at dependency and lifecycle probes — do not create gameplay code before baseline, project-root, and native-binding prerequisites pass.
- Ruling: keep the first implementation round in the main agent — the work is small-to-medium, sequential, and coupled to current governance context — do not spend delegated context merely to parallelize it.
- Ruling: preserve the existing visual producer and tracked baselines — the worktree contains unrelated renderer and golden changes — Godot evidence remains untracked and no baseline-update command is authorized.
- Ruling: bind the pilot only to a machine-readable scenario v23 report — the two historical `perf-baseline*.json` files are actually v15 and v14 — generate a fresh current-client Memory report instead of relabeling or overwriting historical baselines.
- Ruling: after the user revised the pilot to make Python primary, remap the earlier pure-GDScript host work as superseded prototype evidence — preserve the stable pure-GDScript Bootstrap as task 2.4, but do not treat the earlier GDScript feature host and skeleton as completion of revised tasks 2.5–2.8.
- Ruling: stop the Python-primary implementation at task 2.3 — Py4Godot 4.7-alpha21 is the only current release artifact found with Godot 4.7 and macOS arm64 selectors, but it fails the required environment isolation and its editor integration emits runtime errors — do not accept a source fork, launcher-only environment workaround, GDScript feature fallback, or weaker gate without an explicit design revision.
- Ruling: resume only the P1 runtime frontier after the user's explicit 2026-09-16 approval — maintain a minimal, auditable Py4Godot derivative from the already pinned upstream revision; permit changes only to interpreter isolation, editor integration, packaging, and lifecycle correctness; keep all gameplay/data ownership and every qualification gate unchanged; do not begin P2 unless the derivative reaches Go.
- Ruling: accept `4.7-alpha21-mornlea.1` as a P1 Go for the current macOS Apple Silicon target only — the minimal loader/lifecycle patch passes the unchanged isolation, editor/headless, export, coexistence, and 100-cycle matrix — retain the patch deletion conditions and do not infer Windows/Linux qualification or any gameplay/data ownership from this result.
- Ruling: keep the task 2.5 Bootstrap probe pure and fail-closed — it may read project-local artifact paths and descriptor identities but may not instantiate either extension, import a Python feature, or start networking — defer successful dynamic class identity and Python host handoff to the later bridge/host tasks.
- Ruling: separate Godot Python development tooling from the production runtime — keep project dependencies empty, resolve Ruff/mypy only into the ignored `uv` development environment from the lock, execute checks with the exact embedded CPython interpreter, and type against project-owned stubs without importing generated add-on modules.
- Ruling: compose Python features through explicit Godot catalog, manifest, scene, and resource paths — the qualified isolated interpreter intentionally omits the project root from `sys.path`, and Py4Godot loads resource scripts as isolated modules — do not add directory scans, unrestricted dynamic imports, sibling implementation imports, or an ambient Python package root to make feature discovery work.
- Ruling: accept `4.7-alpha21-mornlea.2` as the current macOS Apple Silicon P1 runtime — the additional ordered patch repairs generic generated-wrapper ownership for dynamically loaded RefCounted resources and singleton accessors, exposes no Mornlea gameplay/data API, and passes the unchanged full qualification matrix — keep resource-lifetime repair in the binding derivative rather than adding host-level reference-count workarounds.
- Ruling: keep production feature code Python-led after the pure-GDScript Bootstrap — the five presentation features and three desktop adapters own explicit coarse boundaries, while internal components receive no manifests — reject any new production GDScript outside the two Bootstrap diagnostics and keep audio disabled until its later migration task explicitly enables it.
