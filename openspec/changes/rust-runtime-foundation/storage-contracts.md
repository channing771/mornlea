## Metadata fidelity versus admission/restoration

`encodeMetadata` validates version6 and `Difficulty.Valid()` only (`G/metadata.go:71`–80), then serializes weather byte raw (`:93`). `decodeMetadata` casts byte to WeatherKind without validation (`:184`–186). `DiskStore.SaveMetadata` (`G/disk.go:111`) and `MemoryStore.SaveMetadata` (`G/memory.go:87`) both call that encoder: neither adds weather admission. `NewMemory` directly retains its Metadata argument (`G/memory.go:68`). `OpenDisk` delegates to `decodeMetadata`/`encodeMetadata` (`G/world_files.go:63`, `:80`). Therefore there is **no stricter weather store-admission rule** that can justify the Rust codec check.

Runtime assembly separately normalizes `DayPhaseOffset % DayLengthTicks` (`packages/server/server/server.go:161`) and passes raw weather to `RestoreWeather` (`:165`). `RestoreWeather` clamps kind>Thunder toClear and rolls a duration if remaining0 (`packages/server/sim/runtime/engine.go:158`). Its explicit invalid-weather test is `TestRestoreWeatherClampsIllegalKind`, using `WeatherKind(7)` (`packages/server/sim/runtime/weather_restore_test.go:79`). This is runtime restoration, not codec behavior.

No weather-invalid codec test/reference fixture was found in `G/metadata*_test.go`; existing weather tests cover migration defaults and valid persistence (`G/metadata_weather_test.go:23`, `:49`). Existing current metadata golden is inline `TestMetadataV6GoldenBytes` (`G/metadata_difficulty_test.go:26`); it even uses raw SpawnDimension=-3. Difficulty invalid-byte/current-encode rejection tests already exist (`:290`, `:316`). The raw-weather parity finding is source-inspected and has not been executed.
