# Rust protocol v45 completion — Superpowers implementation plan

> **For agentic workers:** use `superpowers:subagent-driven-development` or `superpowers:executing-plans` task by task. The accepted spec is [specs/rust-runtime-foundation/spec.md](specs/rust-runtime-foundation/spec.md), the architectural contract is [design.md](design.md), and exact fields/limits are in [wire-matrix.md](wire-matrix.md). This file is the only checkbox/status source; linked packets contain execution detail but no second checklist.

**Goal:** make the Rust v45 protocol a complete, bounded, offline-qualified interface consumable by the future Rust server and client core. **Architecture:** raw wire/registry/codec in `mornlea_protocol`, shared semantic values in `mornlea_domain`, Go only as an offline source oracle. **Tech stack:** Rust 1.97.1, Go 1.26, existing zstd, existing schema-2 runtime corpus. **Baseline:** clean `main` at `2750284d`; at implementation start verify registry/version/corpus drift and reconcile this plan before a dependent edit. All packet IDs and validation rows are v45; no save/protocol/ABI bump or default runtime change is authorized.

## Global constraints

- The target runtime has Rust-owned protocol, server and client core; Godot/Python owns presentation and does not parse wire records.
- Go production codecs, transport, saves and default startup remain compatibility sources during this offline change. No source comments gain task IDs, and every new source comment is English.
- F2 creates authority metadata and chooses routing; F1 protocol methods own only bounded wire records and checked semantic conversions. The 2 MiB frame, 64 KiB small packet, 1 MiB compressed snapshot and 2 MiB decoded snapshot ceilings are distinct from the domain's 4,096-record semantic bound.
- Candidate corpus files are exported outside the repository and reviewed before serial merge. Each independently verified node gets a scoped commit; check source-bound derived consumers and relevant `AGENTS.md` whenever ownership or entry points change.

## Review focus

- An old-version handshake and a login with invalid identity plus distance must retain the correct rejection precedence; node [1.4](plans/01-boundaries.md#node-1-4) pins both against the real Go login driver.
- A public packet mutated after construction with a too-short output buffer must report the invalid value first and leave bytes untouched; node [1.2](plans/01-boundaries.md#node-1-2) establishes the writer and every packet group tests it.
- A snapshot claiming excessive expansion, carrying a bad checksum or having a malformed compact palette must fail before publication; node [3.2](plans/03-server.md#node-3-2) owns those cases.
- A nonzero raw container reference with an out-of-range `i32` dimension must never alias a valid `u8` dimension; nodes [1.3](plans/01-boundaries.md#node-1-3) and [2.4](plans/02-client.md#node-2-4) pin both primitive and command use.
- A case can have the right family name while never executing or carrying stale source bytes; nodes [1.1](plans/01-boundaries.md#node-1-1) and [4.3](plans/04-closure.md#node-4-3) reject missing routes, zero cases and provenance drift.

Every node follows red → minimal implementation → focused green → controller review → scoped commit. A test that fails only because a new test file does not exist is not a behavioral red; the packet brief names an actual baseline mismatch or a missing callable boundary and a concrete input. Inspect `-- --list` and reject zero discovered/executed cases. Node closure records source/result SHA, case IDs, corpus digest, command output, review ruling and rollback result in `ledger.md`. The controller alone updates these checkboxes and integrates shared exports, manifest and corpus sources; `Cargo.lock` remains unchanged because this plan adds no dependency. Later nodes never treat earlier source-ported Rust round trips as independent Go parity. No worker may rewrite tracked corpus evidence directly or infer a new contract from a Go implementation detail without returning to the controller.
