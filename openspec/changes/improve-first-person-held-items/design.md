## Context
见 proposal.md。当前 Go 输出 avatar 同布局实例，Rust viewmodel pass 独立清深度，容量为四；资产注册表已有完整 16×16 原创物品图标与分面方块映射。

## Goals / Non-Goals
保持选中、伤害和采掘结果的权威确认，以及 HUD 与第三人称显隐规则。点击挥动改为本地呈现输入驱动。改变主手构图、局部握持及持物几何。不增加副手功能、不升级 ABI 或改变世界掉落物。

## Decisions
- 隐藏左手，主手保留同身份手臂材质、颜色；前臂比例和透视可独立于第三人称调校。全部物品变换乘同一个右手握持根，局部 grip 锚对齐握柄或方块承托点。
- 透明图标优先于 ItemPlacement 分类（火把、门、床也有图标）。在资产缓存刷新阶段，将图标非透明像素转换为有厚度的棱柱描述，可合并同行同色像素以减少实例；颜色取当前图标，按 alpha 阈值 0.5 保留轮廓。注册表拥有不可变缓存，render 只读取。禁止每帧读取纹理或重建几何；默认路径和材质刷新均须接线。
- 方块采用六个薄面部件，各面使用资产注册表对应面材质，整体旋转展示顶面与两个侧面，避免六面同纹理。若复用现有等效分面抽象更小，可沿用但不得改 ABI 布局。
- 实例上限统一提高为 257，Rust/Go 容量、上传和拒绝超量测试同步。96 字节布局、TLV tag、ABI v18 保持不变；仅内部预算变化。预热后编码零分配。
- 工具按剑、镐、锄构建独立握柄、刃体、连接结构与截面层次；共享类别模型并由当前原创素材派生材质颜色，保留损坏缺口，其他图标按类别安排承托点。默认 FOV、16:9 和 4:3 及完整挥动做投影验证。
- 不采用只变颜色的长条、不导入 Minecraft 素材。选择像素棱柱而非只有前后面的薄片，确保侧视仍有实体厚度；同类别不同材料复用结构模型。

## Risks / Trade-offs
- 像素棱柱增加实例 → 最坏约 24.7 KB 实例载荷、固定预分配，尽量合并连续像素；测量分配与预算。
- 图标原画的斜柄造成错误握点 → 针对工具档定义握点，实拍检查全工具和损坏形态。
- 分面薄片边缘与透视 → 离屏实拍检查草、木、工作台及单色方块，确保无漏面或闪烁。
- 隐藏左手改变旧测试假设 → 更新明确涉及旧双手/四实例/长条的断言，保留其权威与投影保护意图。

## Migration Plan
仅客户端呈现，无存档迁移。Go 与 Rust 同批构建；回退本 change 代码恢复旧呈现。视觉演示输出到本 change 工作目录，不自动覆盖既有视觉基线。主规格在归档时同步。

## 用户反馈后的第二轮设计
- 第一轮均匀加厚图标仍像薄片，工具改为有实心截面和分件结构的体素模型；剑有护手、刃脊/刃缘，镐有横向金属头和柄套，锄有偏置刃与连接部。侧面厚度与比例应在中立位即可辨认。
- 根据实际逻辑 viewport 与世界 FOV 调整握持根。HUD 几何以现有前端为准：scale=min((W-16)/476,(H-16)/160,1)，底部热栏宽476、高60，上方生命/饥饿/氧气占至底部106；兼顾最右选中槽上抬和描边。在640×360、1280×720及4:3下验证中立与完整动作，前臂可从右边缘出画以避开热栏。
- 使用本地有效主键上升沿触发即时呈现动作，持键可循环挥动；不依赖 CombatHit 或有效采掘目标。用显式单调呈现 elapsed 输入推进，重放相同输入保持确定，不读取墙钟。延迟命中不重复触发。菜单、背包、聊天、首次捕获鼠标点击不触发，重置清除动作。
- 用户明确要求同时显示 HUD 看样式，因此本轮允许启动隔离世界交互窗口，通过 dev-capture 捕获真实合成截图与点击动作；离屏目录只用于物品覆盖，不作为 HUD 避让证据。不改用户世界或既有视觉基线。
