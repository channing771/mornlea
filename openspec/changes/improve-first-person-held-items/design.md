## Context
见 proposal.md。变更前 Go 输出 avatar 同布局实例，Rust viewmodel pass 独立清深度，容量为四；资产注册表已有完整 16×16 原创物品图标与分面方块映射。当前实施以本文件「已审核效果图落地」及 approved-plan.md 为准，接入主线 client ABI v19。

## Goals / Non-Goals
保持选中、伤害和采掘结果的权威确认，以及 HUD 与第三人称显隐规则。点击挥动改为本地呈现输入驱动。改变主手构图、局部握持及持物几何。不增加副手功能、不升级 ABI 或改变世界掉落物。

## Decisions
- 隐藏左手，主手保留同身份手臂材质、颜色；前臂比例和透视可独立于第三人称调校。全部物品变换乘同一个右手握持根，局部 grip 锚对齐握柄或方块承托点。
- 透明图标优先于 ItemPlacement 分类（火把、门、床也有图标）。在资产缓存刷新阶段，将图标非透明像素转换为有厚度的棱柱描述，可合并同行同色像素以减少实例；颜色取当前图标，按 alpha 阈值 0.5 保留轮廓。注册表拥有不可变缓存，render 只读取。禁止每帧读取纹理或重建几何；默认路径和材质刷新均须接线。
- 方块采用六个薄面部件，各面使用资产注册表对应面材质，整体旋转展示顶面与两个侧面，避免六面同纹理。若复用现有等效分面抽象更小，可沿用但不得改 ABI 布局。
- 实例上限统一提高为 264，Rust/Go 容量、上传和拒绝超量测试同步。96 字节布局、TLV tag、当前主线 ABI v19 保持不变；仅内部预算变化。预热后编码零分配。
- 工具按剑、镐、锄构建独立握柄、刃体、连接结构与截面层次；共享类别模型并由当前原创素材派生材质颜色，保留损坏缺口，其他图标按类别安排承托点。默认 FOV、16:9 和 4:3 及完整挥动做投影验证。
- 不采用只变颜色的长条、不导入 Minecraft 素材。选择像素棱柱而非只有前后面的薄片，确保侧视仍有实体厚度；同类别不同材料复用结构模型。

## Risks / Trade-offs
- 像素棱柱增加实例 → 最坏 25,344 字节实例载荷、固定预分配，尽量合并连续像素；测量分配与预算。
- 图标原画的斜柄造成错误握点 → 针对工具档定义握点，实拍检查全工具和损坏形态。
- 分面薄片边缘与透视 → 离屏实拍检查草、木、工作台及单色方块，确保无漏面或闪烁。
- 隐藏左手改变旧测试假设 → 更新明确涉及旧双手/四实例/长条的断言，保留其权威与投影保护意图。

## Migration Plan
仅客户端呈现，无存档迁移。Go 与 Rust 同批构建；回退本 change 代码恢复旧呈现。视觉演示输出到本 change 工作目录，不自动覆盖既有视觉基线。主规格在归档时同步。

## 用户反馈后的第二轮设计
- 第一轮均匀加厚图标仍像薄片，工具改为有实心截面和分件结构的体素模型；剑有护手、刃脊/刃缘，镐有横向金属头和柄套，锄有偏置刃与连接部。侧面厚度与比例应在中立位即可辨认。
- 根据实际逻辑 viewport 与世界 FOV 调整握持根。HUD 几何以现有前端为准：scale=min((W-16)/476,(H-16)/180,1)，底部热栏宽476、高60，上方生命/饥饿/护甲/氧气占至底部126；兼顾最右选中槽上抬和描边。在640×360、1280×720及4:3下验证中立与完整动作，短斜前臂从右下边缘出画以避开热栏。
- 使用本地有效主键上升沿触发即时呈现动作，持键可循环挥动；不依赖 CombatHit 或有效采掘目标。用显式单调呈现 elapsed 输入推进，重放相同输入保持确定，不读取墙钟。延迟命中不重复触发。菜单、背包、聊天、首次捕获鼠标点击不触发，重置清除动作。
- 用户明确要求同时显示 HUD 看样式，因此本轮允许启动隔离世界交互窗口，通过 dev-capture 捕获真实合成截图与点击动作；离屏目录只用于物品覆盖，不作为 HUD 避让证据。不改用户世界或既有视觉基线。

## 严格实拍复核后的修正（2026-09-14）
用户再次指出右侧手臂、工具呈现和点击动作与目标差距明显。独立测量见 `.superpowers/sdd/approved-plan/strict-visual-audit.md`。该轮以真实游戏视口排除标题栏后测量，替代旧的拳心单点验收。
- 中立袖子主要从底边入画：右边缘交点约95%~98%高，底边左交点约83%~87%宽。拳掌可见局部长轴缩短、横向加厚并做前伸透视；保留独立拇指与握柄环抱轮廓。不能仅平移旧手根。
- 剑保留护手宽度，刃长增加约10%~15%、右倾减少，尖回到约89%宽/20%高。镐单独增大金属头并缩短外露柄，锄缩小连接套并加深偏置刃角；加强身份/材料同源的局部亮暗面。所有目标最终按实际图像复测，不复制世界背景或全局色调。
- 现有动作将0.7幅度乘0.2/0.12后实际只留下约8°俯仰、5°转动，且位置随深度补偿导致几乎原地摇摆。改为显式相位驱动的多轴位移与转动：短预备、快速朝目标击出、较缓回收；空手前冲、镐锄下劈、剑斜斩具有可见差异。
- 挥动可短暂经过准星附近，原来全过程禁止准星交叠的测试不再作为限制；中立准星清楚与全过程HUD不遮挡仍为硬边界。完整轨迹应按真实SwingPhase采样验证，不能沿用单个angle扫描假装覆盖新动作。保持同输入确定、无跳帧突变、固定局部握点、松开收回、界面门控和服务器权威不变。
- 暂不适配小屏幕：不继续为窄屏压小工具或削弱挥动。原有紧凑布局分支可保留，既有桌面16:9/4:3与30/70/110FOV、预算和可见性检查继续覆盖；如旧窄屏测试与本轮桌面目标冲突，记录范围裁决，不偷偷改变测试含义。

最新尺寸裁决：桌面视觉矩阵采用1280×720、1600×900、1280×960。旧640/480/800画幅不再作为本轮视觉门禁，不新增旧模型兼容分支；保留通用安全与预算测试。


用户实机反馈补充：镐的工作段须由尖端领先凿入目标，横向宽镐头侧推不符合预期。只修正镐工作姿态/轨迹，静态审核轮廓和其他类别动作保持；以实际编码尖端、镐头中心及接近方向验证，不能用根旋转幅度代替物理工作朝向。
