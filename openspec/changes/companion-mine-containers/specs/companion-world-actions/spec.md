## MODIFIED Requirements

### Requirement: 伙伴采掘复用玩家计时规则且三方原子

`mine` 步骤 SHALL 先把伙伴带入目标方块的交互距离（复用 `go_to` 的移动与寻路语义），随后按既有玩家采掘规则持续采掘：所需 tick 由 `miningRule`（方块、持握工具）唯一决定，交互距离与 Ready 区块校验与玩家共用同一实现。采掘完成的同一权威 tick 内 MUST 原子完成三方：目标方块改为空气（容器目标 MUST 同时停用其容器槽）、按既有规则扣除工具耐久（含损坏形态）、可收获产物直接加入伙伴 36 格背包；任一方无法完成时该 tick MUST NOT 变更任何一方。

普通方块的采掘目标 MUST 是具有单一 `BlockDrop` 的非容器、非农业方块。箱子与熔炉 MUST 是合法的伙伴采掘目标，其产物是「容器本体 + 全部内容物堆」的批量：结算前 MUST 在伙伴背包副本上逐堆预演，任一堆放不下时该 tick MUST 整体不结算（方块、容器内容物、工具耐久、背包与采掘进度满格状态全部保持，其中进度满格是「就绪但无容量」的稳定可观察状态）。农业方块（八个作物阶段与干湿耕地）MUST 继续被 Planner 契约与权威模拟双重拒绝。伙伴背包没有容纳产物的空位时任务 MUST 以稳定原因失败且 MUST NOT 破坏方块。目标方块在采掘过程中被其他 actor 改变时，采掘进度 MUST 失效并按目标变化语义处理，MUST NOT 破坏新方块。

#### Scenario: 完整采掘链三方原子成立

- **GIVEN** 伙伴背包有一把完好的石镐，交互距离内有一个煤矿石方块
- **WHEN** 采掘按所需 tick 完成的那一权威 tick
- **THEN** 方块 MUST 变为空气、石镐耐久 MUST 按既有规则扣减、对应产物 MUST 直接出现在伙伴背包中，三者 MUST 在同一 tick 内全部成立

#### Scenario: 背包无空位不破坏方块

- **GIVEN** 伙伴 36 格背包已满且交互距离内有一个可采掘方块
- **WHEN** 任务尝试执行采掘
- **THEN** 方块 MUST 保持不变，任务 MUST 以稳定原因失败并广播事件，背包 MUST 不变

#### Scenario: 采掘空箱子批量直入背包

- **GIVEN** 交互距离内有一个空箱子，伙伴背包有空位且手持可收获箱子的工具
- **WHEN** 采掘完成的那一权威 tick
- **THEN** 箱子方块 MUST 变为空气、其容器槽 MUST 同 tick 停用、箱子本体 MUST 进入伙伴背包、工具耐久 MUST 按既有规则扣减，全部变更 MUST 在同一 tick 内成立

#### Scenario: 容器内容物放不下时全或无

- **GIVEN** 交互距离内有一个内容物堆数超过伙伴背包余量的箱子
- **WHEN** 采掘进度达到满格后的结算 tick 与后续 tick
- **THEN** 箱子方块与其全部内容物 MUST 保持原样，工具耐久 MUST 不变，任务 MUST 以 `TaskFailInventoryFull` 失败，采掘进度 MUST 保持满格作为「就绪但无容量」的稳定状态

#### Scenario: 采掘熔炉连带三格内容物

- **GIVEN** 交互距离内有一个熔炉，其输入、燃料、输出三格各有物品，伙伴背包能容纳全部四堆产物
- **WHEN** 采掘完成的那一权威 tick
- **THEN** 熔炉本体与三格内容物 MUST 全部进入伙伴背包，熔炉方块 MUST 变为空气且容器槽同 tick 停用，工具耐久 MUST 扣减

#### Scenario: 农业方块仍然被拒绝

- **GIVEN** 交互距离内分别有一个成熟小麦与一格湿耕地
- **WHEN** 计划包含以其为目标的 `mine` 步骤
- **THEN** 该步骤 MUST 被拒绝（计划校验与权威模拟双重拦截），方块 MUST NOT 被破坏

#### Scenario: 目标变化令进度失效

- **GIVEN** 伙伴正在采掘一个方块且进度已过半
- **WHEN** 其他 actor 在完成前替换了该位置的方块
- **THEN** 既有进度 MUST 失效，任务 MUST 按目标变化语义处理，新方块 MUST NOT 被破坏或继承进度
