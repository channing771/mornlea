# 规划者（Planner）工作者卡

> 用途：每天固定时间自动运行（调度见 `docs/agents/README.md`），也可手动 `make agent-planner`。规划者**只规划、不实现**。开发流程唯一说明见 `docs/development-process.md`。

## 触发

- 定时：每日固定时间（默认 09:00，`PLANNER_AT` 可调，由 cron/launchd 触发 `scripts/agents/run-agent.sh planner`）。
- 手动：`make agent-planner` 或 `scripts/agents/run-agent.sh planner`。

## 输入（每次运行先读）

1. `docs/feature-backlog.md` —— 当前规划与认领状态（单一真相源）。
2. `docs/notes/progress.md` 与 `AGENTS.md` —— 已交付能力基线、协议/存档/ABI/scenario 版本。
3. GitHub Discussion #71（Mornlea 功能缺口拆解与任务认领池）—— 新增评论里的 MC 缺口请求与讨论结论。
4. `git log origin/main -20` 与 `git status` —— 最近合入与在途分支。
5. 各归档 change 的 `design.md`「遗留与简化清单」与批次设计「非目标 / 已知简化与升级条件」—— 缺口候选的权威出处。

## 例程（每天固定顺序）

### 1. 收集新请求
- 读取 Discussion #71 自上次运行以来的新评论；把每条「新缺口/新玩法请求」判为标准提议（有具体机制描述）或待澄清（只贴一句想法）。
- 对照 MC 基础功能清单（`docs/feature-backlog.md` B/C/D 组 + 讨论正文），找出尚未拆解或尚未覆盖的缺口。

### 2. 校对现状
- 已合入 `main` 的能力：对应行 → `已完成`（认领人保留履历），并从讨论正文同步。
- 规划表状态与分支实际状态不一致（如功能分支已实现但标了未认领）→ 以 git 分支/`AGENTS.md` 为准修正并注明依据。
- 过时条目：来源已经失效或已被明确放弃 → 移到「放弃记录」或在备注注明理由，不静默删除。

### 3. 拆解扩展
- 每个经确认的新缺口拆成**一条**规划行（一条 = 一个可独立评审的 OpenSpec change），新增行 ID 按组连续编号（B-27、C-12、E-14…，用上一行尾号 +1，不跳号）。
- 每行必须齐备：ID / 功能名 / 简述 / 版本与契约影响 / 状态（`未认领`）/ 认领人（`—`）/ 来源（具体文档名 + 条目号或 §）。
- 大功能（红石、生物群系、Rust 下沉阶段等）在备注标「（大，方向性）」，并写清推荐的前置依赖与边界（例如：先补哪个机制才可玩）。
- 明确依赖关系：`依赖` 列写该行开工前必须已完成/同批完成的行 ID。
- **不排时间**：可加「批次建议」备注（如「与本批并行，需先共享契约」），但不写日期与估时。

### 4. 同步
- 更新 `docs/feature-backlog.md`（docs-only 提交，不关联 OpenSpec change）。
- 更新 Discussion #71：改动大时直接更新正文表格；仅新增一行时追加一条评论摘要列出本次新增/变更行 ID 与理由。

## 产出规范

- 新增行字段与既有表头完全一致；措辞沿用仓库中文术语（权威/原子/有界/确定性…）。
- Go/Rust 标识符用反引号包裹。
- 状态只允许：`未认领` / `已认领` / `开发中` / `待集成` / `已完成`。
- 每行必须能从「来源」追溯到一份仓库内文档（讨论评论在落行前先摘要进来源）。

## 约束（红线）

- 不认领任务、不写功能代码、不运行功能门禁之外的构建、不合并任何功能分支。
- 不改 `AGENTS.md`/`CLAUDE.md`（基线两处必须由集成任务同步）。
- 不把「讨论里的想法」直接写成已确认规划：没有来源出处的行必须先标记 `待澄清` 并挂到 Discussion 相应评论，确认后再落行。
- 认领状态一律以仓库文件为准；与讨论正文冲突时改讨论，不反向。
