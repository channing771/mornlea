# B-02 水桶 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付空桶/水桶双物品、取/放双命令与经典无限水，使农业摆脱天然水体约束。

**Architecture:** 双显式命令走 TillSoil/BoneMeal 同形路径；无限水为 fluid kernel 规则扩展，四邻≥2源升源，复用现有预算队列与湿度重判。

**Tech Stack:** Go 1.26（core/network/sim/fluid/client）、Rust 1.97.1（mornlea_engine fluid_eval）、engine ABI v10 不变、client ABI 不变。

**Spec:** `docs/superpowers/specs/2026-09-08-b02-bucket-design.md`

## Global Constraints

- 协议 v37→v38，只追加 C→S ID 16/17，不改既有 ID 与布局。
- 物品只能追加在 `ItemIDMax` 哨兵之前：`ItemEmptyBucket=55`、`ItemWaterBucket=56`、`ItemIDMax` 55→57。
- 配方只能追加：`RecipeBucket=20`（紧随 `RecipeIronSword=19`）。
- `ItemPlacement` 永不映射流体；取/放只走专用命令。
- 双桶限 1 堆叠、无耐久、非工具/非食物；跨 goroutine 发送成功后消息不可变。
- Rust kernel 与 Go oracle 必须逐位一致，无 Go 生产 fallback。
