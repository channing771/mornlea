# 红石信号电路战役设计

日期：2026-09-12

## 1. 背景与裁决

2026-09-12 用户要求盘点相对 Minecraft 的系统性缺口并给出一个足够复杂的长任务；控制会话对比 `docs/feature-backlog.md`、`openspec/specs/` 与生存闭环收尾战役设计（`2026-09-11-survival-loop-completion-design.md`）后给出缺口分析，推荐「信号电路（红石类）」方向，用户批准落为正式 umbrella 设计。

定位说明：生存闭环设计 §7 写明「收官后再开新方向的规划讨论」，本设计是用户在该收官点之前显式发起的提前规划；它只完成规划讨论与排队，不提前开工。本设计是规划层产物：不认领任何行、不改变任何行状态、不预占任何版本号。积压表 B-19 维持设计候选，本战役排在生存闭环收尾战役（三阶段十一行）完成之后启动，串行链与版本号互斥规则不变。

方向定位：这是项目的第一个自动化/信号系统。近期产品边界「首夜生存 + 自给家园」的下一步深度自然形态就是家园自动化——压力板开门、信号灯照明、可控农场。Mornlea 已有合成、熔炉、门、火把、流体、生物与伙伴，唯独没有任何「电路」概念。

## 2. 已核实现状（2026-09-12，main `d3c7b1e8`）

- **挂载面已在**：`deterministic-block-updates` 主规格开篇写明单一确定性调度承载全部定时与随机方块更新，「让草蔓延、沙落、红石等后续机制无需再各写一套队列即可挂载」；该调度器已由 E-19（归档 `archive/2026-09-10-unified-block-updates-world-streaming`）交付。
- **确定性地基齐备**：hash 抽样（splitmix64 salt 先例）、流体 Rust/Go 双内核与不动点论证、Go oracle 删除后以位级 golden/确定性孪生补位的门禁先例。
- **状态编码现状是硬约束**：全部方块状态靠 BlockID 家族编码（门 9 形态、小麦 8 阶段、耕地干湿二分），chunk schema v9 无按位置的附加状态字节段；信号强度这类连续量无法沿此家法编码。
- **矿物与洞穴**：矿物只有煤与铁两种，无洞穴 carve（B-37 排队）——红石矿的获取路径与洞穴边界必须一并裁决，否则红石粉没有生存获取链。
- **可复用面**：植物 cross 几何（短草/作物）可承载红石粉呈现；火把先例给出「发光方块增删触发客户端静块光重算」的完整路径；门已有权威开合语义可被供电驱动；B-05 落地判定可作压力板的实体检测先例；伙伴 world actions 为将来「读电路」预留（不在本战役）。
- **不抄 Minecraft 怪癖**：项目「不兼容官方 Minecraft 协议、存档或版权资源」；电路语义自定，明确排除 quasi-connectivity、BUD 之类历史行为怪癖，自定干净语义。

## 3. 目标与非目标

### 3.1 目标

- 电源原语、信号传播、消费者三段闭环：拉杆/按钮/红石火把 → 红石粉网络（强度 15 级衰减的确定性传播）→ 红石灯与供电门。
- 「方块附加状态字节」作为区块 schema 下一版的新基础设施落地（与 B-16 横向原木/薄雪层、B-43 楼梯/半砖共享同一块地基）。
- 供电状态活过存档重启；同种子同输入 tick 重放逐位一致（沿项目确定性教义）。
- 全程无测试后门的生存获取链：红石矿 → 挖掘 → 红石粉 → 搭建电路。

### 3.2 非目标

- 活塞、发射器、漏斗：方块推拉与物品自动化是独立项目量级，显式排除。
- 比较器与中继器全语义：首战役至多做最小延迟/单向中继（且可后移，见 §4）。
- 不复刻 Minecraft 行为怪癖（quasi-connectivity、BUD 等）。
- 不动「服务端不计算光照」禁令：红石灯明灭沿用客户端静块光重算（火把先例）。
- 伙伴读电路/操作拉杆等伙伴集成属 C 组方向，本战役不做。

## 4. 战役结构：五个 change

| 序 | change | 交付 | 关键依赖与裁决 |
|---|---|---|---|
| 1 | 状态字节地基 | chunk schema 附加状态段（容量、默认值、旧档只读迁移、读写路径）+ 红石矿与红石粉获取路径 | 与 B-37 洞穴边界一并裁决 worldgen（见 §5 D5）；与 B-16/B-43 共享基础设施口径 |
| 2 | 电源原语 | 拉杆、按钮（定时脉冲）、红石火把（反相器）；信号强度域定义与邻域求值挂上统一调度器 | 依赖序 1 |
| 3 | 红石粉传播 | 导线放置规则、衰减 15 的确定性传播、遍历序/环路不动点论证、cross 呈现、供电状态持久化 round-trip | 依赖序 2；协议升版（方块更新携带附加状态字节） |
| 4 | 消费者 | 红石灯（静块光重算）、供电门（复用门开合语义） | 依赖序 3 |
| 5 | 中继器与压力板 | 延迟/单向中继；实体检测压力板（沿 B-05 落地判定先例） | 依赖序 4；范围裁决时可整行后移为二期 |

规模感：近三行先例为六至十任务组（树苗八组、空背包六组、统一调度器十组）；本战役五个 change 合计约两个到三个该量级，跨若干周。阶段边界即门禁边界（推送前全量 `test-race` 与 `openspec validate --all --strict`）。

## 5. 关键设计裁决建议

- **D1 状态编码**：BlockID 家族路线对信号强度必然爆炸（16 级 × 连接形态），不可行；推荐在区块 schema 下一版引入按位置的附加状态段。该段是 B-16（原木朝向/薄雪层）与 B-43（楼梯/半砖）共同等待的地基，必须按公共基础设施口径设计（容量与默认值语义、旧档迁移、区块读写单一路径），不得只为红石定制。备选「独立 side schema（沿 `hostile_mobs`/`passive_mobs` 先例）」留作 fallback，代价是方块与状态两套原子性与恢复序。
- **D2 确定性传播**：每次方块变更触发有界网络重算；遍历序、多源汇合与环路解法的总序必须可重放，论证沿流体不动点先例成文；传播预算上限或分帧摊销满足热路径无界工作禁令。
- **D3 Rust/Go 分界**：沿流体先例做单一真源裁决。倾向信号求值入 Rust engine（engine ABI v11→v12，沿 `mornlea_tree_blocks` 的函数追加先例），Go 侧收敛为校验、结算与持久化；避免双实现长期差分。
- **D4 持久化与呈现**：供电状态随附加状态段入区块存取（非独立 schema），保存/恢复 round-trip 与重启后行为不变为硬验收；红石粉走植物 cross 材质路径，强度分级呈现；红石灯明灭走火把先例的光照增删。
- **D5 红石矿可达性**：与洞穴（B-37）时序绑定。倾向本战役整体排在生存闭环战役（含洞穴行）之后，红石矿随洞穴地下化一次改 worldgen，避免两次改新生成区块字节流并重订 golden；若排期提前，需先裁决浅层矿脉或等价来源并把结论写入价值闭包守卫清单。

## 6. 版本与契约影响预估（方向性）

| change | 方向性影响 |
|---|---|
| 状态字节地基 | chunk schema v9→v10（附加状态段）+ 旧档只读迁移；红石矿 worldgen + engine ABI 可能升版 + worldgen golden |
| 电源原语 | 方块/物品编号追加；无 wire 结构变更（交互沿既有 use 语义） |
| 红石粉传播 | 协议升版（方块更新携带附加状态字节）；benchmark scenario 可能升版（电路负载场景） |
| 消费者 | 编号追加；golden 场景追加；大概率无 wire |
| 中继器/压力板 | 编号追加；无 wire |

绝对版本号一律以各行实现时的 main 为准（版本号互斥规则不变）；同一时间只允许一个 change 持有升版槽。

## 7. 完成的定义（验收口径）

1. 电路闭环 e2e：空背包起家链延伸到「铁镐采红石矿 → 红石粉 → 拉杆 + 红石粉 + 红石灯/供电门组成最小电路」，全程无测试后门（沿 `survival_bootstrap_e2e_test.go` 先例）。
2. 确定性：同种子同输入 tick 重放逐位一致；传播遍历序与环路解法有显式论证文档（沿流体先例）。
3. 持久化：通电电路存档/重启后状态与传播行为不变。
4. 版本与基线：涉及升版的各行完成 golden/scenario 重订；既有 golden 零漂移（或经裁决再生并逐图确认）。
5. 价值闭包守卫持续绿：红石粉/红石矿取得真实自然来源后入 `reachability_closure_test.go` 正向断言。

战役收官时在 `docs/notes/progress.md` 记录闭环达成，并回改积压表将本设计标记为已兑现。

## 8. 风险与在案裁决点

- **状态字节地基先行**：若本战役先于 B-16/B-43 启动，附加状态段必须按公共基础设施口径设计，否则后续两行返工；裁决建议已写入 D1。
- **洞穴时序**：红石矿两次 worldgen 改动的成本 vs 战役整体后移；D5 倾向后移，与 2026-09-11「先完善已有方向」裁决一致，但把战役起点压到生存闭环战役完全收官之后，接受。
- **范围蔓延**：Minecraft 红石全家桶（活塞、比较器、发射器、漏斗）的诱惑；非目标已钉死，任何新增面一律另立 change 重新裁决。
- **服务端光照禁令**：若红石灯被裁决需要服务端参与光照，属禁令重裁，与洞穴黑暗生成同面，另行立项，不在本战役。
- **中继器范围**：序 5 的中继器是唯一可整体后移的 change；压力板与中继器可拆分，压力板单独先行不阻塞任何闭环验收。
