# 第一夜生存五路并行批次设计

日期：2026-08-23

状态：设计已批准，等待用户复核本文后再编写实施计划

## 背景

当前 `main` 已交付权威采掘、固定合成、熔炉、箱子、工具耐久、生命、饥饿、昼夜、农业、玩家近战、方块光、流体、远环 LOD、默认材质包和生存 HUD。`fix-grass-block-texture` 也已在共同基线提交。下一批以“熟悉的第一夜生存”为产品目标：机制接近 Minecraft 的常见认知，但继续使用 Mornlea 的原创美术、独立协议、独立存档和服务端权威规则。

本批拆成五个可并行开发、各自工作量充足的垂直闭环：真实格子工作台、五向火把、三级剑战斗、可持久化近战夜怪、床与睡眠。五项分别维护 OpenSpec change、隔离 worktree、implementer 和独立任务评审，最终汇入单一集成分支和单一 PR；任何半完成的 v27 都不得进入 `main`。

## 目标

- 玩家能用 2×2 与工作台 3×3 格子完成形状配方，而不是点击 recipe ID 自动扣料。
- 玩家能制作并放置受支撑约束的落地或墙面火把，以现有方块光照亮夜间空间。
- 木剑、石剑和铁剑对敌怪与玩家共用一套权威命中、冷却、击退和耐久规则。
- 夜间存在一种原创外观、近战行为熟悉、可生成、追击、攻击、死亡、掉落、消失和跨重启恢复的敌怪。
- 双格床能设置个人重生点；全部在线且已出生玩家入睡后只跳昼夜相位，不跳过权威模拟时间。
- 五项全部保持 Memory/TCP 一致、资源有界、失败原子、无前台窗口自动测试，并具备正式视觉门禁。

## 非目标

- 不增加远程敌怪、投射物、护甲、状态效果、难度档位、门或完整生物群系。
- 不导入、临摹或复制 Mojang 的材质、模型、音频或 UI 像素。
- 不建设通用 ECS、插件式物品注册器、脚本配方系统、通用方块事件总线或任意模型描述语言。
- 不让五个功能 PR 依次把半完成批次推入 `main`。
- 本批不支持床跨区块放置；跨区块双记录事务留到确有第二个消费者时再设计。

## 方案选择

### 采用：按功能垂直切片

每个任务从权威规则贯穿到网络、存档、客户端镜像、呈现、测试和 OpenSpec。任务能独立进行规格与质量评审，最终集成只集中处理 append-only 编号、公共版本、长期文档和视觉基线。

### 否决：按技术层横切

把工作拆成 core/network/server/client/render 会让任何单项都无法独立试玩或验收，并把主要风险变成跨任务口头协调。

### 否决：先建设通用扩展框架

先做实体、交互或模型平台会延迟五项同时开工，并提前抽象尚不存在的消费者。这里只冻结已经由两个真实功能共同需要的窄契约。

## 并行与集成结构

五项从同一个包含 `fix-grass-block-texture` 的干净 `main` 建立分支，不分别合入主分支。三个任务先产出可单独评审的窄契约提交，其他任务在等待时继续其余独立部分：

1. 工作台先固定 `ShapedRecipe`、2×2/3×3 grid 和权威产物取出接口；火把、剑和床只追加配方。
2. 火把先固定有限 block model tag 及 registry wire；床只消费既定 `bed` 形态。
3. 剑先固定统一的攻击候选与伤害结果契约；玩家和夜行者不得各写一套命中规则。

最终集成顺序固定为工作台、火把、剑、夜行者、床。分支里的临时枚举值不构成稳定契约；集成分支按本文的统一顺序锁定编号、packet ID、版本注释、规格和 golden。

## 任务一：权威格子工作台

### 行为

背包打开时提供 2×2 crafting grid；玩家对工作台执行既有权威射线交互后打开 3×3 grid。输入格与产物格均由服务端发布。移动物品复用现有两次点击的整堆/拆分语义；只有从产物格取出时才消费当前匹配输入并生成一个完整产物。客户端不得声明产物、数量或匹配结果。

形状匹配忽略外围空行与空列；配方逐条声明是否接受水平镜像。一次取出只执行一次合成，不在本批加入 shift-click 批量合成。

### 关闭与断线不变量

物品从 36 格背包进入 grid 后，服务端在每次取出产物前先模拟“加入产物，再把剩余 grid 全部按稳定规则装回背包”。若无法完整装回，则拒绝取出且状态逐格不变。这个不变量保证关闭、断线或工作台失效时总能把 grid 无损装回背包，因而无需持久化 grid、生成临时掉落或引入恢复界面。

grid 非空期间，任何其他会增加玩家物品的成功路径也必须先验证同一个“grid 可完整装回”不变量；例如自动拾取若会破坏不变量，就把掉落留在世界中而不是塞入背包。玩家死亡前先按该不变量装回 grid，再复用既有完整背包掉落结算。这样关闭界面之外的物品入口也不能挤占预留容量。

### 配方

既有 `1..11` 在 v27 改成熟悉的格子原料与形状：镐、锄使用木棍，熔炉使用圆环圆石，箱子使用圆环木板，面包使用横排小麦，其余保持各自产品意图。随后追加木棍、工作台、火把、木剑、石剑、铁剑和白床配方。单格原木配方可放在任一归一化位置。

工作台物品可放置为普通全立方体工作台方块，可采掘并掉回一个工作台。每个玩家的工作台 grid 相互独立，工作台区块不保存容器槽位。

## 任务二：可放置火把

新增一个火把物品和落地、四向墙面五个稳定方块形态。放置必须命中已加载、实心的合法支撑面；顶部生成落地形态，四个侧面生成对应墙面形态，底面、流体、非实心支撑和未就绪邻格均拒绝。支撑被任何权威方块变化移除时，只检查固定六邻格并在同一有界变化批次中移除失去支撑的火把，产生一个火把掉落。

火把零碰撞、非不透明、发光等级 14。`core.BlockEmission` 成为服务端生成判定与客户端 registry 的单一发光表来源；实际传播仍复用现有客户端静态方块光实现。

engine ABI v7 的 registry 只增加一个有限 model tag，表达既有 cube/plant/fluid 口径以及火把方向、床方向与床半块。Rust 为火把发出固定上界的原创窄柱/墙面倾斜 quad，quad 仍为 8 bytes，继续走 terrain cutout pass，不新增 pipeline、动态 GPU 资源或任意模型格式。

火把配方是煤炭位于木棍上方，产出 4 个火把。`torch-night` 场景同时覆盖落地与墙面形态、近远光衰减、支撑关系和封闭空间无漏光。

## 任务三：三级剑与统一战斗

新增木剑、石剑、铁剑及三个损坏形态，单格上限为 1；配方使用两份对应主材与一根木棍的竖直形状。项目继续沿用“耐久耗尽转为损坏物品”的既有契约，不让剑凭空消失。

持续 primary action 输入保持不变：按住时，攻击者冷却就绪且射线存在合法目标便再次挥击；不新增第二套攻击按键、点击 packet 或客户端攻击预测。一次裁决同时比较最多 8 名玩家和 64 只夜行者，选择三格射线内最近的同维、存活目标；固体遮挡、流体穿透，等距按固定目标 kind 和稳定 ID。未命中实体时继续既有采掘路径。

空手、木剑、石剑和铁剑使用固定递增伤害。成功造成伤害才给剑扣一点耐久；拒绝、未命中、目标保护期和方块遮挡均不扣。统一战斗加入攻击者冷却、目标受击保护和水平击退，并继续先冻结同 tick 的全部意图再统一结算，使互殴双方都能提交该 tick 已成立的攻击。

客户端通过权威玩家状态与私有命中确认呈现冷却、挥击/命中反馈和音效；复用现有 HUD、cuboid entity pass 与预分配音频队列，不预测生命或耐久。

## 任务四：权威近战夜怪

新增原创外观的“夜行者”。它在夜间从 Ready 玩家周围确定性采样的黑暗合法表面生成：候选不能离玩家过近、处在流体或碰撞空间不足，也不能被火把或发光方块照得过亮。候选由世界种子、单调 `WorldTimeTicks` 和坐标导出，不读取全局随机数或遍历 map。

全服最多 64 只，每位玩家附近最多 8 只。全服每 tick 最多验证一个生成候选，最多构造两个不可变 A* 快照；其余工作按稳定 ID 顺延，每只夜行者的待规划请求采用 latest-wins。夜行者选择最近玩家，复用既有整数 A*、路径 revision 重验和 Rust 物理积分。白天露天时持续灼烧；远离全部玩家达到固定期限后消失。

夜行者近身攻击走任务三的统一战斗与玩家既有 `applyDamage` 入口。受伤、死亡与玩家同 tick 意图冻结顺序一致。死亡产生有界数量的腐肉掉落；腐肉复用既有持续进食链路，提供固定少量饥饿和低饱和度，本批不创建中毒或通用状态效果系统。

每只夜行者具有独立稳定 ID、生命、位置、速度、攻击冷却与必要 AI 状态。独立 `hostile_mobs` schema v1 固定最多 64 条记录，使用现有原子保存、异步合并与关服屏障纪律；未来版本、CRC、长度、重复 ID 或非法状态稳定拒绝且不得覆盖旧文件。正常重启不能成为清怪手段。

网络新增有界、按 ID 严格排序的 spawn/state/despawn 消息，状态批次最多 64 条。客户端不为敌怪生成名牌，复用 avatar cuboid pass 并使用独立 entity kind、原创轮廓和固定调色。avatar 容量从 11 具身体扩为 75 具身体，即 450 个 80-byte cuboid instance；name-tag 容量保持不变。

## 任务五：床、睡眠与个人重生点

新增白床物品，以及脚部/头部乘四个方向的八个稳定方块形态。放置要求脚部与头部都在同一已加载区块、两格均可替换且下方可支撑；两格写入与扣除一张床在一个权威变化批次中原子提交。跨区块、空间不足或任一支撑无效时整体拒绝。破坏任一半会有界移除另一半并只掉落一张床。

床使用 engine ABI v7 已冻结的 `bed` model，生成原创低矮双格几何与相符碰撞体，不增加第二套网格实现。

玩家在夜间对完整床交互后进入权威 sleeping 状态；白天、床无效或附近存在存活夜行者时拒绝。睡眠期间移动、采掘、攻击、进食和容器输入停止。受伤、断线或床被破坏会退出睡眠。全部在线且已出生玩家都处于睡眠后，服务端调整昼夜 offset 到下一清晨并唤醒所有人；PendingSpawn 会话不计入分母，单人世界因此能立即跳夜。

`WorldTimeTicks` 继续每个真实权威 tick 恰好增加 1，并继续驱动伙伴 deadline、作物抽样与模拟顺序。metadata v3 新增取值 `0..23999` 的 `DayTimeOffsetTicks`，v2 迁移值为 0；显示相位按 `(WorldTimeTicks mod 24000 + DayTimeOffsetTicks) mod 24000` 计算，避免先做无界加法。睡眠只改变 offset，不虚构数千次未执行的饥饿、作物、敌怪或伙伴推进。敌怪生成、露天灼烧、天空和客户端都读这一个显示相位；offset 的 wire 字段随 v27 权威玩家状态发布，客户端不得自行跳时。

成功入睡同时把完整床位置写为个人重生点。玩家 schema v8 从 v7 迁移时没有个人床点；死亡时先确认床两半、方向和相邻安全空间仍成立，否则回退现有世界出生锚点。个人床点不替换世界 metadata 中的全局出生锚点。

## 固定资源与编号

最终 append-only 顺序为：

- 物品：木棍、工作台、火把、木剑、石剑、铁剑、三个损坏剑、腐肉、白床。
- 方块：工作台、五种火把形态、八种床半块。
- 配方：更新后的既有 `1..11`，随后是木棍、工作台、火把、木剑、石剑、铁剑、白床。

当前 mesh registry 实际使用 45 项，新增 14 个方块后为 59 项；上限由 48 提升到 64，Go 与 Rust 的三处容量及输入字节上限同步，不再为未规划模型预留更大空间。

夜行者全服 64、每玩家附近 8；一次战斗候选集固定不超过 72；`HostileStates` 固定不超过 64；avatar 身体固定不超过 75；工作台 grid 固定不超过 9；火把支撑反应固定检查六邻格。每 tick 最多执行一次敌怪生成候选验证，方块光判定只在候选周围半径 14 的固定局部窗口内运行并复用预分配 scratch，不建设服务端全世界光照缓存。所有热路径上限都必须由边界测试和相应 benchmark 锁定。

## 失败与恢复

- 配方不匹配、产物或剩余 grid 无法完整装回时，输入、背包与产物逐格不变。
- 火把无支撑、床跨区块或双格条件不成立时，不扣物品、不写部分方块。
- 攻击冷却未就绪、遮挡、未命中或目标保护期不扣耐久、不抑制后续 tick 输入。
- 白天睡眠、附近有夜行者或床无效只产生稳定拒绝；等待其他玩家睡眠不是失败。
- metadata、玩家或敌怪保存继续异步执行；最终关服屏障失败必须返回错误，不得声称保存成功。
- 非法 packet 在现有信任边界按协议错误处理；普通玩法拒绝使用稳定 `RejectReason`，不以断线代替业务拒绝。
- 任何存档迁移只读旧记录并写新记录；未来版本和损坏记录不得被当前程序覆盖。

## 视觉验证

新增五个正式无窗口场景：`workbench-crafting`、`torch-night`、`sword-combat`、`hostile-mob`、`bed-sleep`。最终顺序精确为 `terrain-noon`、`hud-hotbar-health`、`hud-survival-feedback`、`avatar-nametag`、`inventory-crafting`、`workbench-crafting`、`chest-container`、`furnace-container`、`debug-panel`、`skylight-tunnel`、`block-light-room`、`torch-night`、`materials-showcase`、`target-block-feedback`、`oak-grove`、`ai-companion`、`sword-combat`、`hostile-mob`、`bed-sleep`、`water-surface-slope`、`far-horizon`、`water-underwater`。现有末三项的相对位置与倒数约束保持不变。

集成分支只执行一次最终 golden 更新：用同一最终二进制按固定顺序生成完整 22 张正式图，逐图人工检查工作台格子与产物、五向火把与光衰减、剑冷却/命中反馈、敌怪原创呈现、双格床/睡眠，以及所有既有地形、材质、HUD、容器、伙伴、水与远环语义。既有双阈值不得放宽，测试不得创建或聚焦前台窗口。

## 测试与评审

每个任务遵循 RED-GREEN-REFACTOR，并由独立 reviewer 同时给出规格合规与代码质量裁决。至少覆盖：

- 工作台：形状归一化/镜像、2×2/3×3 可达性、取出原子性、关闭/断线装回不变量和 Memory/TCP parity。
- 火把：五方向、支撑移除、流体/底面拒绝、发光等级、跨区段光 dirty 和 Rust 几何边界。
- 剑：玩家/敌怪最近目标、方块遮挡、同 tick 互殴、冷却、击退、耐久与私有确认。
- 夜行者：确定性生成、光照拒绝、数量上限、A* 过期结果、攻击/灼烧/死亡/掉落/消失、存档 golden/fuzz/故障注入和双传输 parity。
- 床：同区块双格原子性、跨区块拒绝、全员条件、受伤/断线唤醒、时间 offset 持久化、个人床点恢复和失效回退。

五项完成后进行整分支终审，并一次执行 Rust build/fmt/clippy/tests、受影响包 race、`go test ./... -race`、`go vet ./...`、archcheck、`gofmt -l .`、OpenSpec strict、scenario v20 benchmark、22 图 visual update/check 和单一集成 PR 的完整远端 CI。性能数值只记录；报告完整性、真实 overflow、数据丢失、I/O 与资源上限仍是门禁。

## 已知简化与升级条件

- 床只允许同区块放置；只有第二个必须跨区块原子写入的玩法出现时，才设计通用跨区块事务。
- 本批只有一种近战夜怪；远程怪出现时再引入投射物协议和命中模型。
- 腐肉没有负面状态；有第二个需要持续状态效果的物品或攻击时，再建设有界状态效果系统。
- block model 是固定 tag，不是数据驱动模型格式；只有多个新增形态无法由有限 tag 清晰表达时才升级。
- 夜行者复用现有 A* 与物理，不提取通用 ECS 或 AI 框架；出现第二类行为显著不同的 mob 后再评估共享边界。
