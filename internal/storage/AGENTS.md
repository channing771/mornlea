# 持久化

## 格式与迁移

- 当前 schema 号只在各 codec/metadata 的代码权威常量中维护；指南和新测试不要复制动态版本数字。
- 旧版本通过逐版本只读迁移加载，写出只使用当前格式；高于当前版本的数据必须拒绝。迁移不得猜测无法从旧数据恢复的玩家意图。
- 编解码入口必须先守住文件、记录、计数和解压上限，再分配或遍历负载。

## 数据安全

- 独立文件更新沿用临时文件写满、sync、close、rename、父目录 sync 的原子替换路径；rename 前失败保留旧文件，rename 后的持久性错误要准确报告提交状态。
- `Close` 对 nil 和重复调用保持安全，停止新工作后释放 region、文件锁和其他资源，并汇总关闭错误。
- 任何格式或写入改动都要覆盖容量上限、故障注入、损坏输入、重启恢复和零数据丢失；不得通过放宽上限或忽略 I/O 错误让测试通过。
- 本包不得依赖 `internal/network`；线上消息与落盘 DTO 在 server 装配层转换。

## 定点验证与入口

- 测试：`go test ./internal/storage -race -count=1`。
- 当前文档入口：`openspec/specs/local-data-migration/spec.md`。
